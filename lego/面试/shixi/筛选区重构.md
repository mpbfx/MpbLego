## 筛选区重构总结

### 问题背景
资源管理页面（`interpreterAndSuppliers.vue` 和 `onSite.vue`）在筛选区输入时出现明显卡顿。根本原因是 Vue 的响应式机制：当筛选字段变化时，会触发整个页面组件（3000+ 行代码，包含 50 行表格）的重新渲染。

### 解决方案
将筛选区提取为独立子组件，利用 Vue 组件边界隔离重渲染范围。输入时只触发筛选组件内部重渲染，不影响父页面的表格区域。

### 修改文件

| 文件                                                   | 操作 | 说明                                  |
| ------------------------------------------------------ | ---- | ------------------------------------- |
| `components/ResourceFilter/ResourceFilter.vue`         | 新建 | 资源开发管理页筛选组件                |
| `components/ResourceFilter/OnSiteFilter.vue`           | 新建 | 资源在场管理页筛选组件                |
| `pages/resourceManagement/interpreterAndSuppliers.vue` | 修改 | 引入 ResourceFilter，移除内联筛选代码 |
| `pages/resourceManagement/onSite.vue`                  | 修改 | 引入 OnSiteFilter，移除内联筛选代码   |
| `config/path.js`                                       | 修改 | 添加在场资源 API 路径配置             |

### 架构变化

**重构前：**
```
Page Component (3000+ lines)
├── 筛选区 (内联模板 + data + methods)
├── 表格区
└── 弹窗等
```

**重构后：**
```
Page Component
├── <ResourceFilter /> ← 独立组件，内部状态变化不触发父组件重渲染
├── 表格区
└── 弹窗等
```

### 组件通信

筛选组件通过事件向父组件传递筛选参数：
- `@search` - 搜索框回车/点击搜索
- `@filter` - 点击筛选按钮
- `@reset` - 点击重置按钮

父组件接收参数后调用 `applyFiltersWithParams(params)` 发起 API 请求。

### API 参数映射

**onSite.vue 关键映射：**
- `translatorLevel` → `payload.level`
- `orderTimeRange` → `payload.latestOrderTime`
- `motherTongue` → `payload.language`
- `relatedProject` → `payload.associatedProjectName`
- `resourceType` → `payload.translatorType`

### 新增 API 路径 (config/path.js)
```javascript
getStoredResourcePage: '/sales/resource/getStoredResourcePage',
searchStoredResourceListByCondition: '/sales/resource/searchStoredResourceListByCondition',
```

### 保持一致性
- 样式：使用 grid 布局，与原样式完全一致
- 功能：筛选字段、选项值、API 参数映射均与原实现一致
- 状态持久化：展开/收起状态仍保存在 localStorage
