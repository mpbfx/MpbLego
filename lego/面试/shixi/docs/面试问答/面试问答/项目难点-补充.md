# 项目难点补充（big-customer，面向面试）

> 说明：本文件补充 `docs/面试问答/项目难点-总结.md:1` 里未覆盖但同样“高频追问/容易踩坑”的工程难点，并配关键代码摘录与文件行号。

## 1. 难点：Nuxt 插件配置的“隐形坑”（对象键覆盖导致插件失效）

### 为什么难

- Nuxt `plugins` 支持用对象配置 `{ src, mode }`；但在 JS 对象里同名键会被覆盖。
- 一旦写成一个对象里两个 `src`，实际只会生效最后一个，属于“看起来配了、实际上没加载”，排查成本很高。

### 关键代码摘录

来源：`nuxt.config.js:67`

```js
plugins: [
  '@/plugins/http',
  {
    src: '@/plugins/errorCodeHandler', mode: 'client',
    src: '@/plugins/checkPermission', mode: 'client'
  },
]
```

### 面试追问（你要能答）

- 为什么这会导致 `errorCodeHandler` 没生效？（对象键覆盖：后者覆盖前者）
- 你会怎么修？（拆成两个对象，或直接用数组项分别声明）

## 2. 难点：两套 Axios 封装并存（$http vs $api）导致行为与返回值形态不一致

### 为什么难

- 项目里既有 `$http`（`plugins/http.js:5`）也有 `$api`（`plugins/axios.js:3`），两者都基于 `$axios.create()`，但拦截器与返回值策略不同。
- `$http` 在 `onResponse` 里 `return response.data`（改变返回值形态），而 `$api` 的 `onResponse` 不 return（保持 axios 原始响应链），调用方容易混淆。

### 关键代码摘录

来源：`plugins/http.js:28`

```js
instance.onResponse(response => {
  if (response.data.errorCode === 1003) { /* redirect */ }
  return response.data
})
```

来源：`plugins/axios.js:34`

```js
api.onResponse(response => {
  if (response.data.errorCode === 1003) {
    redirect(`${path.loginUrl}=${process.env.WEBSITE_HOST}${route.fullPath}`)
  }
  // 注意：这里没有 return response.data
})
```

### 面试追问（你要能答）

- 为什么“返回值形态”是难点？（解构/错误处理/日志埋点会不统一）
- 你会如何收敛？（统一注入一个实例、统一拦截策略、写一套 mock/测试防回归）

## 3. 难点：环境配置穿透与“绝对 URL”导致环境不一致（尤其是文件上传）

### 为什么难

- 业务后端 baseURL 通常走 `API_HOST`，但上传接口在 `config/path.js` 里是硬编码线上域名。
- 这会导致：即使在 test/dev 环境，上传也可能直连线上网关；同时绕过统一请求层与代理策略。

### 关键代码摘录

来源：`config/path.js:94`

```js
uploadFile: 'https://fapi.youdao.com/zuul/base-api/uploadFile',
```

来源：`utils/resource/useResumeFile.js:104`

```js
const uploadRes = await context.$axios.post(path.uploadFile, formData, {
  headers: { 'Content-Type': 'multipart/form-data' }
})
```

### 面试追问（你要能答）

- 为什么这会影响多环境一致性？（绕过 API_HOST/CI 配置，导致测试与线上行为不同）
- 你会怎么改？（把上传网关也纳入 env 配置或走 server 端转发；并在 CI/文档里明确）

## 4. 难点：多 UI 库 + 全局样式覆盖的隔离与可维护性（/deep + body class）

### 为什么难

- 项目同时使用 AntD 与 Element，覆盖第三方组件内部结构需要 `/deep/` 或全局选择器，容易引发样式污染与优先级问题。
- translator 子站通过给 `body` 打主题 class 来“限制影响范围”，这是工程化折中，但仍需要谨慎维护选择器。

### 关键代码摘录

来源：`layouts/translator.vue:85`

```js
mounted() {
  document.body.classList.add('translator-theme')
},
beforeDestroy() {
  document.body.classList.remove('translator-theme')
}
```

来源：`layouts/translator.vue:323`

```css
body.translator-theme .tag-selector-modal {
  /* 译员平台主题覆盖 */
}
```

来源：`components/Nav/Nav.vue:159`（示例）

```css
/deep/.ant-menu-light {
  /* 覆盖第三方组件内部样式 */
}
```

### 面试追问（你要能答）

- 为什么不用 scoped 就完事？（第三方组件内部 DOM 不在当前 SFC scope 内，覆盖需要穿透）
- 如何减少样式污染？（主题前缀、组件封装、减少全局覆盖、逐步引入 CSS 变量/设计令牌）
