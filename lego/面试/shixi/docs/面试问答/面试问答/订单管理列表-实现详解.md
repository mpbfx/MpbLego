## 1. 一句话概括（面试开场）

订单管理列表是运营/PM/销售的“工作台”，核心是：

- **高维筛选**（客户/项目/订单/PM/销售/多日期区间/多状态/语言方向）

- **导出**（总表、结算单）
- **精确搜索模式**（从客户维度带 `userId` 直达其订单）

对应实现集中在：`pages/orderManagement/orderList.vue:1`。

## 3. 筛选模型：为什么拆成 `Obj` + `ObjContainer`

页面把筛选状态拆成两份：

- `searchOrderListObj`：最终要发给后端的“扁平字段”（字符串日期、status 字符串等）
- `searchOrderListObjContainer`：更适合组件绑定的“UI 容器字段”（range-picker 的数组、status 的数组）

来源：`pages/orderManagement/orderList.vue:794`

```js
searchOrderListObjContainer: {
  addOrderDate: null,
  translateDate: null,
  sendBillDate: null,
  incomeDate: null,
  rebateDate: null,
  status: [],
},
searchOrderListObj: {
  userContent: '',
  projectName: '',
  orderName: '',
  pmName: '',
  addOrderDate1: '',
  addOrderDate2: '',
  // ...
  sellerName: '',
  status: '',
  srcLang: '',
  desLang: '',
},
```

面试讲法：

- range picker 绑定需要数组（`[moment, moment]`），但后端接口通常要 `date1/date2` 两个字符串，所以用 `Container` 存 UI 值，用 `Obj` 存落库/传参值。
- 多选状态同理：UI 是数组，接口入参是字符串（join）。

## 4. 首屏 SSR：asyncData 如何把“路由 query”映射到筛选态

该页 `asyncData` 会解析 query 并“预填筛选 + 首次查询”，典型场景：

- `username`：自动按客户名称搜索（非精确模式）：`pages/orderManagement/orderList.vue:910`
- `type`：按预设状态组合筛选（使用 `salesManagerTypeMatchStatusMap`）：`pages/orderManagement/orderList.vue:921`、`pages/orderManagement/orderList.vue:923`
- `datetime`：按月份生成交付日期区间：`pages/orderManagement/orderList.vue:933`
- `sellerName`：销售维度过滤：`pages/orderManagement/orderList.vue:955`
- `precisionSearch`：强制带 `salesUserId`：`pages/orderManagement/orderList.vue:974`

最终统一走接口：`searchSalesOrderListByCondition`（`pages/orderManagement/orderList.vue:982`）。

面试讲法：

- 这是“可分享链接/可从外部跳转”的典型实现：筛选状态完全由 URL 驱动，方便运营把筛选后的列表链接发给别人。

## 5. 查询动作：searchOrder 如何组装 payload（含精确模式）

来源：`pages/orderManagement/orderList.vue:1232`

```js
const playload = {
```

- 请求类型用 `'query'`（urlencoded）：`plugins/http.js:68`（已在 HTTP 文档中解释）。

## 6. 权限与按钮显示：为什么要“权限 + 条件”双重控制

列表页的几个关键动作都做了：

1) **权限控制**（`v-checkPermission`）  
2) **业务条件控制**（必须已搜索、状态筛选必须唯一命中某个节点）

例如“一键提单”按钮：

- 权限：`ordermanagement-onekeySendBill`（`pages/orderManagement/orderList.vue:240`）
- 条件：必须 `modalConfig.searched === true` 且状态筛选仅包含 `100`（`pages/orderManagement/orderList.vue:246`）

对应代码摘录：

```vue
<!-- pages/orderManagement/orderList.vue:234 -->
<span
  v-checkPermission="{
    roleType: $store.state.userinfo.roleType,
    label: 'ordermanagement-onekeySendBill',
  }"
>
  <a-button
    v-if="
      modalConfig.searched &&
      Array.isArray(searchOrderListObjContainer.status) &&
      searchOrderListObjContainer.status.includes(100) &&
      searchOrderListObjContainer.status.length === 1
    "
    class="add-new"
    @click="batchOrder('confirmOrderArraysSendBill')"
    type="default"
    icon="plus"
  >

  </a-button>
</span>
```

面试讲法：

- 权限解决“谁能做”，条件解决“什么时候能做”。两者分离能减少误操作。

### C) updateOrderList：把“操作类型”映射到“字段 + 状态文本”

来源：`pages/orderManagement/orderList.vue:1275`

- 批量（array）：`confirmOrderArraysSendBill → sendBillTime + statusStr='已提单'` 等（`pages/orderManagement/orderList.vue:1291`）
- 单行（single）：`cancelOrderSendBill → sendBillTime='' + statusStr='已交付'` 等（`pages/orderManagement/orderList.vue:1309`）

对应代码摘录：

```js
// pages/orderManagement/orderList.vue:1275
updateOrderList(data, type) {
  const updateSameColumns = (idArray, key, value) => {
    this.orderList.forEach((orderInfo) => {
      if (idArray.includes(orderInfo.id)) {
        orderInfo[key] = value
      }
    })
  }
  const changeSingleRow = (id, key, value) => {
    this.orderList.forEach((orderInfo) => {
      if (orderInfo.id === id) {
        orderInfo[key] = value
      }
    })
  }

  if (type === 'array') {
    const typeKeyMap = {
      confirmOrderArraysSendBill: 'sendBillTime',
      confirmOrderArraysRebate: 'rebateFinishTime',
      confirmOrderArraysIncome: 'incomeFinishTime',
    }
    const statusStrMap = {
      confirmOrderArraysSendBill: '已提单',
      confirmOrderArraysRebate: '已回款',
      confirmOrderArraysIncome: '已确认',
    }
    const key = typeKeyMap[data.type]
    const value = data.confirmDate
    const idArray = this.selectedRowKeys
    const statusStr = statusStrMap[data.type]
    updateSameColumns(idArray, key, value)
    updateSameColumns(idArray, 'statusStr', statusStr)
  }

  if (type === 'single') {
    const typeKeyMap = {
      cancelOrderSendBill: 'sendBillTime',
      cancelOrderIncome: 'incomeFinishTime',
      cancelConfirmOrderRebate: 'rebateFinishTime',
      confirmFileTranslated: 'translateFinishTime',
      confirmOrderSendBill: 'sendBillTime',
      confirmOrderIncome: 'incomeFinishTime',
      confirmOrderRebate: 'rebateFinishTime',
      cancelOrderTranslateFinish: 'translateFinishTime',
    }
    const statusStrMap = {
      cancelOrderSendBill: '已交付',
      cancelOrderIncome: '已提单',
      cancelConfirmOrderRebate: '已确认',
      confirmFileTranslated: '已交付',
      confirmOrderSendBill: '已提单',
      confirmOrderIncome: '已确认',
      confirmOrderRebate: '已回款',
      cancelOrderTranslateFinish: '翻译中',
    }
    const key = typeKeyMap[data.type]
    const value = data.confirmDate
    const statusStr = statusStrMap[data.type]
    const id = data.id
    changeSingleRow(id, key, value)
    changeSingleRow(id, 'statusStr', statusStr)
  }
},
```

面试讲法：

- 这是“前端状态机”的小型实现：服务端更新成功后，前端只更新必要字段，避免重新请求导致页面滚动/选择丢失。

## 9. 导出：为什么用拼 URL 的方式（而不是 axios blob）

总表导出：

来源：`pages/orderManagement/orderList.vue:1461`

```js
let downloadURL = path.baseURL + path.exportSalesOrdersToExcel + '?' + qs.stringify(playload)
window.location.href = downloadURL
```

结算单导出同理：`pages/orderManagement/orderList.vue:1478`。

面试讲法：

- 传统后端导出多用 `Content-Disposition` 触发浏览器下载，直接跳转 URL 最简单、兼容性最好。
- 如果要更强可控（文件名、错误提示），可以改成 `fetch blob + a[download]`（项目在“上传下载”专题里已有范式）。

## 11. 交互细节：表头吸顶与潜在风险

页面在 `mounted` 里直接挂 `window.onscroll` 给表头加/删 class（`pages/orderManagement/orderList.vue:999`），并在 `destroyed` 清理（`pages/orderManagement/orderList.vue:1025`）。

面试官追问你可以这样答：

- 当前实现简单有效，但对 DOM 结构依赖强（`getElementsByClassName('ant-table-thead')[1]`）；
- 更稳的做法是：用 `position: sticky` 或者在 antd table 容器内监听 scroll（而不是 window）。

## 12. 常见坑 & 可改进点（面试加分）

1) `status` 的 join/解析契约：后端如果改成数组入参，需要统一调整 `searchOrder/export/batch` 三处（`pages/orderManagement/orderList.vue:1243`、`pages/orderManagement/orderList.vue:1463`、`pages/orderManagement/orderList.vue:1599`）。
2) 批量操作快照校验目前失败会 reload：更优是“禁用选中变更/按钮 loading”或“以弹窗打开时的 idArray 为准”。
3) 导出使用 `window.location.href` 无法给出失败提示：可升级为 `fetch` + 错误码解析。
4) 批量导入弹窗与 `components/OrderDetail/BatchImportModal.vue` 存在重复：可统一为一个组件，减少维护面。
