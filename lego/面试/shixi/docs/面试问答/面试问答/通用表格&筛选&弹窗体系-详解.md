> 目标：把项目里常见的“筛选区复用、表格列自定义、弹窗式交互（登录/文件预览/评价与沟通记录）”的通用实现模式讲清楚，并能指到关键代码（`file:line`）。

## 1. 一句话概括（面试开场）

这个项目的复用主要体现在“UI 交互范式”而不是抽象成一个大框架：

- **筛选区组件化**：开发池/在场池把筛选 UI 抽成组件，通过 `$emit('filter')/$emit('reset')` 和父页面解耦（`components/ResourceFilter/ResourceFilter.vue:275`）。  
- **列自定义**：通过 `CustomColumnDropdown`（AntD Dropdown + CheckboxGroup）把“可见列”写入 localStorage，做到用户偏好记忆（`components/Table/CustomColumnDropdown.vue:40`）。  
- **弹窗体系**：  
  - 登录：第三方 URS 组件嵌入 `el-dialog`（client-only），登录后回填 Vuex 并 `location.reload()` 保证 SSR 状态同步（`components/LoginDialog/login.vue:72`、`components/LoginDialog/login.vue:191`）。  
  - PDF 预览：动态 import `vue-pdf-embed`，用 fetch `credentials: 'include'` 拉取受 cookie 保护的文件并做自适应缩放（`components/PdfPreviewModal.vue:178`、`components/PdfPreviewModal.vue:195`）。  
  - 资源沟通/评价：弹窗组件提供 `open(row)` 方法，自动填充当前用户信息并提交到后端接口（`components/ResourceDialog/CommunicationDialog.vue:83`）。

## 3. 筛选区复用（ResourceFilter / OnSiteFilter）

### 3.1 组件与页面的契约：只通过事件通信

来源：`components/ResourceFilter/ResourceFilter.vue:275`

筛选组件不会直接请求接口，而是把“用户意图”通过事件发给父页面：

- `search`：通常只带关键词
- `filter`：带全量 form 条件
- `reset`：通知父页面恢复默认

好处（面试讲法）：

- 筛选 UI 与数据请求解耦，父页面负责“组装参数 + 调接口 + 刷表格”；  
- 组件可复用到多个页面，且便于单测（只测 emit 是否正确）。

### 3.2 折叠/展开状态记忆：localStorage（只在 mounted 读）

来源：`components/ResourceFilter/ResourceFilter.vue:235`、`components/ResourceFilter/ResourceFilter.vue:272`

- 组件在 `mounted` 读 `resource_filter_expanded`（避免 SSR 访问 localStorage）。  
- 用户切换展开状态时写回 localStorage，刷新后保持一致。

在场筛选同理，key 是 `onsite_filter_expanded`（`components/ResourceFilter/OnSiteFilter.vue:195`、`components/ResourceFilter/OnSiteFilter.vue:229`）。

### 3.3 筛选 form 的“可重置性”：createEmptyForm()

来源：`components/ResourceFilter/ResourceFilter.vue:241`

`createEmptyForm()` 返回一个完整的默认对象；`reset` 时直接覆盖 `this.form = this.createEmptyForm()`，避免逐字段清空漏掉字段。

## 4. 自定义列（CustomColumnDropdown）：v-model + localStorage

来源：`components/Table/CustomColumnDropdown.vue:29`

这个组件的复用点在于两个约定：

1) **v-model 友好**：通过 `this.$emit('input', selectedKeys)` 支持 `v-model`（`components/Table/CustomColumnDropdown.vue:38`）。  
2) **持久化是可选的**：由 `storageKey` 决定是否写 localStorage（`components/Table/CustomColumnDropdown.vue:29`、`components/Table/CustomColumnDropdown.vue:40`）。

面试讲法：

- 把“状态持久化”做成可选能力，组件更通用（有的页面不需要记忆）。
- `storageKey` 由调用方决定，避免不同页面互相覆盖。

## 5. 登录弹窗（LoginDialog）：第三方 URS + SSR 同步

### 5.1 client-only + el-dialog：避免 SSR 访问 window/document

来源：`components/LoginDialog/login.vue:1`

URS 脚本与 DOM 操作都只能在客户端运行，因此用 `<client-only>` 包裹，并在打开弹窗时动态加载脚本。

### 5.2 登录成功后的状态回填：写 Vuex + 强制刷新

来源：`components/LoginDialog/login.vue:191`

登录回调中会：

- 调用接口获取用户信息（译员平台走 `isValidUser`，大客户系统走 `getUserInfo`）
- `commit` 到 `userinfo` 与 `authUser`
- 最后 `location.reload()`，确保 SSR/CSR 状态一致（避免只更新了客户端 store，服务端仍认为未登录）。

## 6. PDF 预览弹窗（PdfPreviewModal）：受保护资源的稳定预览

### 6.1 动态 import 组件 + 配 worker：解决 SSR 与 pdf.js worker 路径问题

来源：`components/PdfPreviewModal.vue:53`、`components/PdfPreviewModal.vue:116`

- `VuePdfEmbed` 以动态 import 方式加载，避免 SSR 侧直接 require 到浏览器依赖。
- `mounted` 里设置 `pdfjs.GlobalWorkerOptions.workerSrc`，解决 worker 找不到导致无法渲染的问题。

### 6.2 fetch 带 cookie：`credentials: 'include'`

来源：`components/PdfPreviewModal.vue:178`

预览和下载都用 `fetch(url, { credentials: 'include' })`，这是典型的“文件下载接口需要 cookie 登录态”的处理方式。

### 6.3 自适应缩放：按容器宽高计算 fitScale

来源：`components/PdfPreviewModal.vue:195`

`fitToContainer()` 会取容器可用宽高、用 `pdfDoc.getPage()` 拿 viewport，再计算缩放比，保证不同屏幕/弹窗尺寸下可读性。

## 7. 资源沟通/评价弹窗：open(row) + 自动填充 + 提交接口

### 7.1 open(row) 作为外部入口（imperative API）

来源：`components/ResourceDialog/CommunicationDialog.vue:83`、`components/ResourceDialog/EvaluationDialog.vue:133`

弹窗组件对外暴露 `open(row)`，父组件通常通过 `ref` 调用：

- 自动补齐 `resourceId/translatorId`
- 默认评价人/沟通人取 `store.state.userinfo.userName`
- 默认日期填今天

### 7.2 提交接口统一走 $http + path 枚举

来源：`components/ResourceDialog/CommunicationDialog.vue:133`、`config/path.js:1`

提交时使用 `this.$http.post(path.createResourceCommunication, payload)` 这类形式：

- 好处：接口路径集中管理；HTTP 层统一处理 `errorCode`、cookie 与错误逻辑。  

## 8. 面试题库（Q&A 速记）

### Q1：筛选组件为什么不在组件内部直接请求接口？

因为接口请求与分页/排序/缓存策略通常属于“页面级状态”；组件只负责收集条件并通过事件输出，复用性更强、耦合更低。

### Q2：为什么自定义列要用 `storageKey` 做可选持久化？

不同页面的列集合不同；把 key 交给调用方可以避免冲突，并且允许某些页面不持久化（例如敏感页面或临时页面）。

### Q3：PDF 预览为什么要把 URL 先 fetch 成 blob 再渲染？

受保护资源通常依赖 cookie；先 fetch 成 blob 可以稳定处理登录态、跨域策略、以及统一错误提示（失败时提示“直接下载”），并且能避免 viewer 直接加载 URL 时的不可控行为（`components/PdfPreviewModal.vue:165`）。
