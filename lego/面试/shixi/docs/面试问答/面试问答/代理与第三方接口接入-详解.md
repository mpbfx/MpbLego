# 代理与第三方接口接入（Nuxt proxy + QWeather GeoAPI）详解（big-customer，面向面试）

## 1. 一句话概括（面试开场）

项目通过 `@nuxtjs/proxy` 把第三方接口（和风天气 GeoAPI）挂到本域路径 `/qweather/*` 下：前端代码只请求 `/qweather/...`，由 Nuxt server 代理转发到真实域名并 `pathRewrite` 去掉前缀，从而规避浏览器跨域并隐藏第三方域名（`nuxt.config.js:88`、`nuxt.config.js:114`、`utils/geoApi.js:5`）。

## 3. Nuxt proxy 配置：/qweather -> 真实域名

来源：`nuxt.config.js:88`

```js
modules: [
  '@nuxtjs/axios',
  '@nuxtjs/proxy',
  'cookie-universal-nuxt',
],

axios: {
  proxy: true,
},

proxy: {
  '/qweather': {
    target: 'https://kt65nnb7q3.re.qweatherapi.com',
    pathRewrite: {
      '^/qweather': ''
    },
    changeOrigin: true
  }
}
```

面试讲法：

- **请求入口统一**：业务代码永远请求本域 `/qweather/...`，不直接依赖第三方域名。
- **CORS 规避**：浏览器端请求到本域（同源），由 Nuxt server 去访问第三方。
- `pathRewrite`：把 `/qweather/geo/v2/city/lookup` 转成 `/geo/v2/city/lookup` 再发给第三方。
- `changeOrigin: true`：把 `Host`/`Origin` 等改成目标域名，提升第三方接入兼容性。

## 4. 第三方接口封装：GeoAPI 城市搜索

来源：`utils/geoApi.js:1`

```js
import axios from 'axios'

const QWEATHER_KEY = '520569efd2e244c78eabc18c0d94a618'
// 实际请求会被转发到: https://kt65nnb7q3.re.qweatherapi.com/geo/v2/city/lookup
const GEO_API_URL = '/qweather/geo/v2/city/lookup'

export async function searchCity(keyword, countryCode = '') {
  const res = await axios.get(GEO_API_URL, {
    params: {
      location: keyword,
      lang: 'zh',
      range: 'world',
      number: 20,
      key: QWEATHER_KEY
    },
    timeout: 5000
  })

  if (res.data && res.data.code === '200') {
    let list = res.data.location
    // 去重并返回 label/value 结构
    const seen = new Set()
    const uniqueList = []
    for (const item of list) {
      if (!seen.has(item.name)) {
        seen.add(item.name)
        uniqueList.push(item)
      }
    }
    return uniqueList.map(item => ({ label: item.name, value: item.name, key: item.id, raw: item }))
  }
  return []
}
```

面试讲法：

- 这里没有用项目的 `$http/$axios` 插件，而是直接引入了 `axios`（第三方请求与业务后端请求隔离）。
- 返回值被标准化为 `{ label/value/key }`，方便直接喂给下拉/搜索组件。
- `timeout: 5000` 是“第三方接口要快失败”的典型策略，避免拖慢表单交互。

## 5. 调用方：译员基础信息里做城市联想（防抖 + 国家过滤）

来源：`utils/resource/useTranslatorBasicInfo.js:188`

```js
handleCitySearch: debounce(async function (value) {
  if (!value?.trim()) return
  const countryInput = context.basicInfoEditing.country || context.basicInfoEditing.province
  const countryCode = getCountryCode(countryInput)
  if (countryCode === 'CN') {
    const allCities = getChineseCities()
    context.cityOptions = allCities.filter(c => c.includes(value))
    return
  }
  const results = await searchCity(value, countryCode)
  context.cityOptions = results.map(item => item.label)
}, 500)
```

面试讲法：

- **先本地后远程**：CN 走本地城市列表过滤，避免外部依赖；非 CN 才调用第三方 GeoAPI。
- **防抖**：输入联想典型用 `debounce(500ms)` 降低请求频率、保护第三方额度与性能。

## 6. 安全与工程化视角（面试加分项）

1) `QWEATHER_KEY` 目前硬编码在前端（`utils/geoApi.js:2`），即使走 proxy 也仍会暴露给浏览器/抓包：更安全的做法是把 key 放到服务端（环境变量）并在 serverMiddleware 里拼接，前端不直接持有 key。  
2) 代理只能解决 CORS 和隐藏域名，**不能**替代鉴权：第三方 key 的额度/权限仍需要服务端控制。  
3) 可观测性：建议在 proxy 层加日志/熔断（超时、失败率）或缓存热点结果（城市联想很适合缓存）。

## 7. 面试题库（Q&A 速记）

### Q1：为什么不用浏览器直接请求第三方？

主要是 CORS、域名依赖与安全：通过 Nuxt proxy 统一入口，避免跨域限制，也便于未来切换第三方服务（`nuxt.config.js:114`）。

### Q2：`pathRewrite` 有什么用？

把对内统一前缀 `/qweather` 去掉，让目标服务收到符合它路由定义的路径（`nuxt.config.js:117-119`）。

### Q3：第三方 key 怎么保护？

理想方案是 key 不下发到客户端，放在服务端（环境变量/密钥管理），由 server 代签或拼接；前端只调用本域的受控接口。
