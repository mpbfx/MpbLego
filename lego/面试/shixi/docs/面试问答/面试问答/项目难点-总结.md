## 3. 难点 1：CI/CD 与 CDN 版本化交付（最“系统性”的坑）

### 为什么难

- 静态资源不是跟着 SSR 服务一起发，而是走 **SVN/CDN 版本目录**；SSR 部署顺序一旦错（先切服务、后上 CDN），就会 chunk 404。
- 版本号由 CI 用 `awk` 硬解析（格式一改就挂），并且 publicPath 必须跟 SVN 目录结构严格一致。

### 关键代码摘录

来源：`env.js:11`、`nuxt.config.js:133`

```js

```

```js
// nuxt.config.js（节选）
build: {
  publicPath: projectEnv.BUILD_PUBLIC_PATH,
}
```

来源：`.gitlab-ci.yml:26`、`.gitlab-ci.yml:40`

```yml

- export testVersion=`echo $line1 |awk -F ''\''' '{print $2}'`
...
```

### 面试追问（你要能答）

- 为什么不用“镜像内 build”而要 CI build + CDN？（缓存/首屏/静态分发/发布策略）
- 版本回滚怎么做？（回切 `CI_COMMIT_SHA` 镜像 + 回指 CDN 版本目录）

### 改进点（加分）

### 15.3 故障复盘卡片（面试高频）

1) 现象：发布后静态资源 404，页面白屏。  
- 影响：线上新版本不可用。  
- 定位：SSR 服务已切新版本，但 CDN 目录仍旧版本。  
- 止血：回滚镜像到上一个 `CI_COMMIT_SHA`，CDN 切回旧版本目录。  
- 根因：部署顺序缺少“CDN ready”前置检查。  
- 长期修复：发布流水线增加“目录探测 + hash 校验 + 原子切换”。

2) 现象：用户主动退出后刷新又变成已登录。  
- 影响：登录态体验不一致。  
- 定位：SSR `nuxtServerInit` 仍按 cookie 判定已登录。  
- 止血：加入 `logged_out=1` 兜底并优先判断。  
- 长期修复：补充登录态 e2e 用例（登录-退出-刷新-再访问）。

3) 现象：测试环境上传命中线上网关。  
- 影响：多环境不一致，存在风险。  
- 定位：上传接口写死绝对 URL，绕过 env/proxy。  
- 止血：临时切换环境变量。  
- 长期修复：上传网关统一走配置中心与 server 侧转发。
