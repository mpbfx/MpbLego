# 上传 / 下载 / 文件预览详解（big-customer，面向面试）

> 目标：把项目里的“文件如何上传、如何保存文件元数据、如何下载、如何做 PDF 预览（含鉴权 cookie）”讲清楚，并能指到对应代码。

## 1. 一句话概括（面试开场）

本项目的文件链路是一个“两段式”模型：

1) **先上传文件到文件服务**，拿到 `keyName`（对象存储 key）  
2) **再把 keyName + fileName + fileType 作为业务数据保存到业务表**（如资源简历、合同字段、语言证书附件等）

下载/预览时统一走：`GET {baseURL}{downloadFile}?keyName=...&fileName=...`，并用 `fetch(..., { credentials: 'include' })` 携带 cookie，保证鉴权可用（`utils/resource/useResumeFile.js`、`components/PdfPreviewModal.vue`）。

## 3. URL 规则与鉴权：为什么要 encode + credentials

### A) baseURL 与下载接口

来源：`config/path.js:1`

```js
const path = {
  baseURL: process.env.API_HOST,
  // ...
  uploadFile: 'https://fapi.youdao.com/zuul/base-api/uploadFile',
  downloadFile: '/sales/resource/downloadFile',
  translatorDownloadFile: '/sales/user/downloadFile',
}
```

面试讲法：

- `baseURL` 来自运行时环境 `API_HOST`（Nuxt 注入，常见于 SSR/CSR 统一配置）。
- `downloadFile/translatorDownloadFile` 是**相对路径**，最终拼到 `{baseURL}{path}`。
- `uploadFile` 是**绝对 URL**（硬编码域名），这会带来“不同环境下上传仍打到线上域名”的风险（可以作为改进点讲）。

### B) 为什么必须 `encodeURIComponent(fileName)`

文件名可能包含中文、空格、括号等字符，不编码会导致：

- querystring 被截断、空格变 `+` 解析不一致
- 后端 `Content-Disposition` 文件名乱码

因此代码里普遍会：

- `encodeURIComponent(file.name)`（`utils/resource/useResumeFile.js:161`）
- `encodeURIComponent(this.contractInfo.contractFileName)`（`pages/resourceManagement/resourceDetail/_id.vue:3825`）

### C) 为什么用 `fetch(..., { credentials: 'include' })`

项目很多下载接口是**需要登录态 cookie** 的（尤其是跨域、SSR 代理后真实域不同的场景）。  
用 `credentials: 'include'` 可以保证：

- 浏览器把 cookie 一起带上
- 下载/预览不会因为 401/302 导致空白

对应代码：`utils/resource/useLanguageLevel.js`、`components/PdfPreviewModal.vue`。

## 4. 上传：a-upload / beforeUpload 为什么要 `return false`

在 Ant Design Vue 的 `<a-upload>` 里，本项目常用 `:before-upload="xxx"` 并且 **返回 false 阻止默认上传**，原因是：

- 我们需要把“上传文件到文件服务”改成**自定义请求**（带 cookie / 自定义 headers / 统一错误提示）
- 上传成功后还要**写业务表**（例如简历表、合同字段、证书附件数组），默认上传无法覆盖这一步

示例（合同上传）：`pages/resourceManagement/resourceDetail/_id.vue:292`

```vue
<a-upload
  :before-upload="onUploadContract"
  :show-upload-list="false"
  accept=".pdf"
>
  <a-button type="primary" size="small">上传文件</a-button>
</a-upload>
```

对应逻辑：`pages/resourceManagement/resourceDetail/_id.vue:3771`

```js
async onUploadContract(file) {
  const formData = new FormData()
  formData.append('file', file)
  const uploadRes = await this.$axios.post(path.uploadFile, formData, {
    headers: { 'Content-Type': 'multipart/form-data' }
  })
  if (uploadRes.data.errorCode === 200 && uploadRes.data.fileInfo) {
    this.contractInfoEditing.contractFile = uploadRes.data.fileInfo.keyName
    this.contractInfoEditing.contractFileName = file.name
  }
  return false
}
```

面试讲法（强调“两段式”）：

- 这里只完成了第 1 段：拿到 `keyName` 并暂存到编辑态。
- 第 2 段通常发生在“保存表单”动作里：把 `keyName` 一起提交给后端落库（合同模块的保存在同文件其它方法中）。

## 5. 简历文件（资源模块）：上传后落库 + 并行加载列表

### A) 文件类型策略：resume / bvc / portfolio

来源：`utils/resource/useResumeFile.js:27`

```js
const FILE_TYPE_CONFIG = {
  resume: { fileType: 1, accept: '.pdf', multiple: true, errorMsg: '简历仅支持PDF格式' },
  portfolio: { fileType: 2, multiple: false, maxCount: 1, errorMsg: '作品集仅支持1个文件' },
  bvc: { fileType: 3, accept: '.doc,.docx,.pdf', multiple: true, errorMsg: 'BVC仅支持Word或PDF格式' }
}
```

讲法要点：

- 用“策略表”把不同文件类型的限制集中起来（扩展名、是否单文件、提示语）。
- `portfolio` 强制单文件，上传前会检查是否已有文件（`utils/resource/useResumeFile.js:91`）。

### B) 上传闭环：上传文件服务 → 写资源简历表 → 刷新列表

来源：`utils/resource/useResumeFile.js:74`

```js
const uploadRes = await context.$axios.post(path.uploadFile, formData, {
  headers: { 'Content-Type': 'multipart/form-data' }
})

const requestData = {
  resourceId: context.resourceId,
  fileName: file.name,
  keyName: uploadRes.data.fileInfo.keyName,
  fileType: config.fileType
}
await context.$http.post(path.createResourceResume, requestData)
await this.loadResumeFiles()
```

面试讲法：

- “文件服务返回 keyName”与“业务表记录”彻底解耦：后端可以随时换存储实现，前端只关心 keyName。
- `loadResumeFiles()` 统一刷新 UI，避免本地拼数据导致一致性问题。

### C) 并行加载三类文件：Promise.allSettled

来源：`utils/resource/useResumeFile.js:264`

```js
const [resumeRes, portfolioRes, bvcRes] = await Promise.allSettled([
  context.$http.get(path.getResourceResumeByResourceIdAndType, { resourceId, fileType: 1 }),
  context.$http.get(path.getResourceResumeByResourceIdAndType, { resourceId, fileType: 2 }),
  context.$http.get(path.getResourceResumeByResourceIdAndType, { resourceId, fileType: 3 })
])
```

讲法要点：

- `allSettled` 的好处是“部分失败也能展示其它成功的数据”，体验更稳。

## 6. 下载：为什么不用 window.open，而是 fetch + blob + a[download]

在资源模块里，下载普遍采用 `fetch → blob → URL.createObjectURL → a.click()`，原因：

- 可以强制指定 `link.download = 原始文件名`（避免后端未设置 `Content-Disposition` 时文件名丢失）
- 可以统一携带 cookie（`credentials: 'include'`）

示例（合同查看态下载）：`pages/resourceManagement/resourceDetail/_id.vue:3822`

```js
fetch(url, { method: 'GET', credentials: 'include' })
  .then(r => r.blob())
  .then(blob => {
    const blobUrl = window.URL.createObjectURL(blob)
    const link = document.createElement('a')
    link.href = blobUrl
    link.download = this.contractInfo.contractFileName
    link.click()
    window.URL.revokeObjectURL(blobUrl)
  })
```

译员平台合同下载同理：`pages/translator/contract.vue:397`。

## 7. 预览：两种策略（新开页 / PDF 弹窗内嵌）

### A) 简单策略：window.open（让浏览器处理）

语言证书附件预览：`utils/resource/useLanguageLevel.js:250`

```js
const url = `${path.baseURL}${path.downloadFile}?keyName=${file.keyName}&fileName=${encodeURIComponent(file.fileName)}`
window.open(url, '_blank')
```

优点：实现最简单。  
缺点：如果下载接口返回的是二进制而非可内嵌 PDF，浏览器行为不一致。

### B) 复杂策略：PDF 弹窗（fetch 成 blob 再喂给 vue-pdf-embed）

通用弹窗：`components/PdfPreviewModal.vue`

```js
const resp = await fetch(this.pdfUrl, { credentials: 'include' })
const raw = await resp.blob()
const pdfBlob = raw.type && raw.type.includes('pdf') ? raw : new Blob([raw], { type: 'application/pdf' })
this.blobUrl = URL.createObjectURL(pdfBlob)
```

补充（现网实现）：

- 组件级 SSR 兜底：`VuePdfEmbed` 通过 `process.client ? import(...) : Promise.resolve(...)`，避免 Node 端解析 `self` 报错。
- worker 兼容：`mounted` 中加载 `pdfjs-dist/legacy/build/pdf` 并设置 `GlobalWorkerOptions.workerSrc`，规避私有字段语法兼容问题。
- 重复请求去重：弹窗组件有 `lastLoadedUrl`，同一 URL 且已存在 `blobUrl` 时不重复拉取。
- 自适应缩放：`fitToContainer()` 用 `pdfDoc.getPage().getViewport()` 计算 scale，保证弹窗尺寸变化后仍可读。

译员平台合同页使用该弹窗：`pages/translator/contract.vue:175`，把预览 URL 拼好后传入：

```js
this.pdfPreviewUrl = `${path.baseURL}${path.translatorDownloadFile}?keyName=${this.sealedContractFile}&fileName=${encodeURIComponent(this.sealedContractFileName)}`
this.pdfPreviewVisible = true
```

译员“简历预览页”是同思路的页面级实现：`pages/translator/resumePreview.vue`

- 路由来源支持 `?from=contract|resume`，动态切换面包屑返回路径/标题。
- 支持 `url#page=2` 这类 hash 页码，首屏按指定页打开。
- 预览失败时给出下载兜底文案，避免纯空白页。

面试加分点：

- “先 fetch 成 blob 再渲染”能绕开部分浏览器的跨域/鉴权限制（直链 iframe 可能拿不到 cookie 或被拦）。
- 失败时会提示用户走下载兜底（弹窗与预览页都具备）。

## 8. 与业务封装的结合：HTTP 层如何支持 formData

批量导入用到了统一的 `$http.post(..., 'formData')` 分支（`plugins/http.js:67`）：

```js
post: (url, data, type) => {
  if (type === 'formData') {
    return instance({ method: 'post', url, data, headers: { 'Content-Type': 'multipart/form-data' } })
  }
}
```

使用方：`components/OrderDetail/BatchImportModal.vue:139`。

说明：

- 资源模块里“上传到文件服务”多用 `$axios.post`（因为要直连 `uploadFile` 完整 URL）。
- “写业务表/查列表”统一走 `$http`（项目约定返回结构 `errorCode/data/message`）。

## 9. 常见坑与可改进点（面试官追问）

1) `uploadFile` 硬编码域名（`config/path.js:94`）：多环境切换时容易“上传打到生产域名”，建议改为相对路径 + `baseURL` 或用 env 控制。
2) 下载/预览必须带 cookie：所有 `fetch` 记得 `credentials: 'include'`，否则容易在生产环境出现“预览空白/下载失败”。
3) 文件名必须编码：统一封装一个 `buildDownloadUrl(keyName, fileName, isTranslator)`，减少遗漏。
4) 预览策略统一：当前同时存在 `window.open` 与弹窗/预览页两套，建议按文件类型（PDF/非 PDF）与鉴权要求统一封装（例如统一的 `openFilePreview` 工具）。
