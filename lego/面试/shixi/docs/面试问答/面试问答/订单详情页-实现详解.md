# 订单详情页-实现详解（big-customer，面向面试）

> 目标：把订单详情页的“卡片化拆分、SSR 并发拉取、结算节点一致性、生产记录编辑/评价、与资源模块联动”讲清楚，并能指到代码。

## 1. 一句话概括（面试开场）

订单详情页采用“**卡片化 + SSR asyncData 并发拉取 + 局部刷新**”的方式，把一个订单拆成：

- 客户信息（订单基础信息 + 结算节点联动）
- 生产信息（译员生产记录、单独编辑日期、删除、跳资源详情）
- 收益信息（毛利率、低毛利提示）
- 操作记录（审计/追溯）

实现入口：`pages/orderManagement/orderDetail.vue:1`。

---

## 2. 页面结构：为什么用卡片拆分

模板层把每个业务域放到一个 card 组件里：

- 客户信息：`components/OrderDetail/Cards/CustomerInfoCard.vue:1`（`pages/orderManagement/orderDetail.vue:14`）
- 生产信息：`components/OrderDetail/Cards/ProductionInfoCard.vue:301`（`pages/orderManagement/orderDetail.vue:34`）
- 收益信息：`components/OrderDetail/Cards/ProfitInfoCard.vue:1`（`pages/orderManagement/orderDetail.vue:53`）
- 操作记录：`components/OrderDetail/Cards/OperationRecordCard.vue:1`（`pages/orderManagement/orderDetail.vue:73`）

对应代码摘录：

```vue
<!-- pages/orderManagement/orderDetail.vue:11 -->
<customer-info-card
  ref="customerInfoCard"
  :order-info="orderInfo"
  :editable="orderInfoEditable"
  @save="saveCustomerInfo"
/>

<div v-if="orderId && !isSalesRole" class="card-section">
  <production-info-card
    :records="orderTranslateRecordList"
    @save-row="saveProductionRow"
    @delete-row="deleteProductionRow"
    @save-date="saveProductionDate"
  />
</div>

<div v-if="orderId" class="card-section">
  <profit-info-card :profit-data="orderProfitList" />
</div>

<div v-if="orderId && !isSalesRole" class="card-section">
  <operation-record-card :records="orderOperationRecordList" />
</div>
```

面试讲法：

- 把“一个超大页面”拆成“多个可维护子域”，每张卡对外只暴露 props + events，主页面只负责编排数据流。
- 好处：需求变更只影响某一张卡；也便于复用（例如 ProductionInfoCard 的行内日期编辑/二次确认逻辑独立维护）。

- 模板控制：`v-if="orderId && !isSalesRole"`（`pages/orderManagement/orderDetail.vue:33`、`pages/orderManagement/orderDetail.vue:72`）

```vue

<!-- pages/orderManagement/orderDetail.vue:71 -->
```

## 4. SSR asyncData：并发拉取的核心数据（新建 vs 编辑）

### A) 新建订单（无 query.id）

无 id 时，asyncData 会：

- 拉销售名单：`getSalesManagerNameList`（`pages/orderManagement/orderDetail.vue:261`）
- 给出默认 `pmName/statusStr`（`pages/orderManagement/orderDetail.vue:263`～`pages/orderManagement/orderDetail.vue:267`）
- 尝试读取 PM 最近订单作为“预填模板”：`getPmLastOrderInfo`（`pages/orderManagement/orderDetail.vue:268`）

对应代码摘录：

```js
// pages/orderManagement/orderDetail.vue:251
const sellerNameListRes = await app.$http.get(path.getSalesManagerNameList)
const sellerNameOptions = sellerNameListRes.data || []
const pmName = store.state.userinfo.userName
const statusStr = '待处理'

let orderInfo = { pmName, statusStr }

const pmLastOrderInfoRes = await app.$http.get(path.getPmLastOrderInfo)
if (pmLastOrderInfoRes.errorCode === 200 && pmLastOrderInfoRes.data) {
  // ... 读取上一单作为预填模板
}
```

返回的数据里 `orderId=null`，页面 mounted 时会强制客户信息卡进入编辑态（`pages/orderManagement/orderDetail.vue:374`）。

### B) 编辑订单（有 query.id）

有 id 时，asyncData 用 `Promise.all` 并发拉取：

- 订单主体：`getSalesOrderById`（`pages/orderManagement/orderDetail.vue:320`）
- 客户信息：`getSalesUserByOrderId`（`pages/orderManagement/orderDetail.vue:321`）
- 操作记录：`getOrderOperationRecordList`（`pages/orderManagement/orderDetail.vue:322`）
- 生产记录：`getOrderTranslateRecordList`（`pages/orderManagement/orderDetail.vue:323`）
- 收益：`getSalesOrderProfit`（`pages/orderManagement/orderDetail.vue:324`）

对应代码摘录：

```js
// pages/orderManagement/orderDetail.vue:300
const payload = { id }
const [
  sellerNameListRes,
  orderListRes,
  orderInfoRes,
  orderOperationRecordListRes,
  orderTranslateRecordListRes,
  salesOrderProfitRes
] = await Promise.all([
  app.$http.get(path.getSalesManagerNameList),
  app.$http.get(path.getSalesOrderById, payload),
  app.$http.get(path.getSalesUserByOrderId, payload, 'query'),
  app.$http.get(path.getOrderOperationRecordList, payload),
  app.$http.get(path.getOrderTranslateRecordList, payload),
  app.$http.get(path.getSalesOrderProfit, payload, 'query')
])
```

并把生产记录统一补上 `translateRecordConfig`，用于前端编辑态控制（`pages/orderManagement/orderDetail.vue:340`）。

面试讲法：

- 并发拉取提升首屏性能；数据结构做“前端态扩展”，把 UI 所需的控制字段与后端原始数据隔离。

## 5. 客户信息保存：一次保存里同时处理“结算节点”一致性

### A) 更新订单基础信息（非结算字段）

编辑态保存会先把结算字段剥离，避免直接把结算字段写入订单基础接口：

- 结算字段列表：`settlementKeys`（`pages/orderManagement/orderDetail.vue:388`）
- 基础 payload 走 `updateSalesOrder`：`pages/orderManagement/orderDetail.vue:406`

```js
// pages/orderManagement/orderDetail.vue:388
const settlementKeys = ['translateFinishTime', 'sendBillTime', 'incomeFinishTime', 'rebateFinishTime']
// pages/orderManagement/orderDetail.vue:398
const basicFormData = { ...formData }
settlementKeys.forEach(key => { delete basicFormData[key] })
// pages/orderManagement/orderDetail.vue:406
await this.$http.post(`${path.updateSalesOrder}?id=${this.orderId}`, payload)
```

### B) 结算节点“先取消再确认”：保证链路方向正确

保存成功后，会按两段处理结算节点：

1) **先取消（逆向回滚）**：回款 → 确认 → 提单 → 交付（`pages/orderManagement/orderDetail.vue:422`）  
2) **再确认（正向推进）**：交付 → 提单 → 确认 → 回款（`pages/orderManagement/orderDetail.vue:433`）

对应 API 映射表：

- cancel：`cancelOrderTranslateFinish / cancelOrderSendBill / cancelOrderIncome / cancelConfirmOrderRebate`（`pages/orderManagement/orderDetail.vue:409`）
- confirm：`confirmFileTranslated / confirmOrderSendBill / confirmOrderIncome / confirmOrderRebate`（`pages/orderManagement/orderDetail.vue:415`）

对应代码摘录：

```js
// pages/orderManagement/orderDetail.vue:409
const cancelApiMap = {
  translateFinishTime: path.cancelOrderTranslateFinish,
  sendBillTime: path.cancelOrderSendBill,
  incomeFinishTime: path.cancelOrderIncome,
  rebateFinishTime: path.cancelConfirmOrderRebate
}
const saveApiMap = {
  translateFinishTime: path.confirmFileTranslated,
  sendBillTime: path.confirmOrderSendBill,
  incomeFinishTime: path.confirmOrderIncome,
  rebateFinishTime: path.confirmOrderRebate
}

for (const key of [...settlementKeys].reverse()) { /* cancel */ }
for (const key of settlementKeys) { /* confirm */ }
```

面试讲法（这是亮点）：

- 结算节点具备“依赖关系”，不能简单覆盖。这个实现用“先回滚再推进”把状态链路固定化，避免出现“回款时间存在但确认时间被清空”这种不一致。

### C) 局部刷新：只刷新客户信息 + 操作记录

保存完成后不会整页刷新，而是：

- 刷新客户信息：`refreshCustomerInfo`（`pages/orderManagement/orderDetail.vue:486`）
- 刷新操作记录：`refreshOperationRecord`（`pages/orderManagement/orderDetail.vue:979`）
- 卡片切回 view：`pages/orderManagement/orderDetail.vue:450`

对应代码摘录：

```js
// pages/orderManagement/orderDetail.vue:458
async refreshCustomerInfo() {
  const payload = { id: this.orderId }
  const [orderListRes, orderInfoRes] = await Promise.all([
    this.$http.get(path.getSalesOrderById, payload),
    this.$http.get(path.getSalesUserByOrderId, payload, 'query')
  ])
  // ... this.orderInfo = { ...orderList[0], userName: ... }
},

// pages/orderManagement/orderDetail.vue:953
async refreshOperationRecord() {
  const payload = { id: this.orderId }
  const res = await this.$http.get(path.getOrderOperationRecordList, payload)
  this.orderOperationRecordList = res.data || []
}
```

## 6. 新建订单：客户选择的难点与预填策略

新建时会先用 `searchSalesUserList` 找 `salesUserId`，再调用 `addSalesOrder` 创建：

- 找客户 id：`pages/orderManagement/orderDetail.vue:462`
- 创建：`pages/orderManagement/orderDetail.vue:469`
- 创建后跳转详情：`pages/orderManagement/orderDetail.vue:473`

面试讲法：

- “新建订单”最大的坑是 customerId 的确定：UI 上选的是客户名，落库要用 id，因此需要一次映射查询。
- 同时做了“最近订单预填”（`getPmLastOrderInfo` / `getPmAndUserLastOrderInfo`），减少重复录入。

## 7. 生产信息：记录的增删改与日期单独编辑

### A) ProductionInfoCard 的职责边界

ProductionInfoCard 把复杂交互封装在组件内部：

- 表格列与行内编辑：`components/OrderDetail/Cards/ProductionInfoCard.vue:304`
- 表单校验（必填、两位小数）：`components/OrderDetail/Cards/ProductionInfoCard.vue:507`
- 修改结算日期/删除“待结算”记录的二次确认（含“输入确认文案”）：  
  - 保存时：`components/OrderDetail/Cards/ProductionInfoCard.vue:580`  
  - 行内日期：`components/OrderDetail/Cards/ProductionInfoCard.vue:887`  
  - 删除：`components/OrderDetail/Cards/ProductionInfoCard.vue:629`

主页面只接收事件并落库：

- 保存行：`saveProductionRow`（`pages/orderManagement/orderDetail.vue:619`）
- 删除行：`deleteProductionRow`（`pages/orderManagement/orderDetail.vue:805`）
- 保存单独日期：`saveProductionDate`（`pages/orderManagement/orderDetail.vue:866`）

对应代码摘录：

```js
// pages/orderManagement/orderDetail.vue:866
async saveProductionDate(record, dateType) {
  const payload = {
    id: this.orderId,
    translateRecordId: record.id,
    confirmDate: record[dateType],
    beizhu: record.beizhu
  }

  let apiPath
  if (dateType === 'translateFinishDate') apiPath = path.confirmRecordTranslated
  if (dateType === 'incomeFinishDate') apiPath = path.confirmTranslateRecordIncome

  const res = await this.$http.post(apiPath, payload, 'query')
  if (res.errorCode === 200) {
    await this.refreshProductionInfo()
  }
}
```

### B) 新增生产记录：为什么要“先新增再补日期”

新增生产记录使用 `addSalesOrderTranslateRecord`（`pages/orderManagement/orderDetail.vue:654`）。  
如果新增时带了交付/结算日期，代码会：

1) 先新增记录  
2) 刷新生产列表拿到新记录 id  
3) 再调用 `updateSalesOrderTranslateRecord` 分别更新交付/结算日期（`pages/orderManagement/orderDetail.vue:662`～`pages/orderManagement/orderDetail.vue:712`）

面试讲法：

- 这是典型的“后端新增接口不支持带日期字段/或日期逻辑复杂”的补救方案：用两步保证数据一致性。

### C) 单独编辑日期：更轻量、但仍保留二次确认

主页面提供 `saveProductionDate(record, dateType)`，根据 dateType 映射到后端确认接口：

- 交付日期：`confirmRecordTranslated`（`pages/orderManagement/orderDetail.vue:876`）
- 结算日期：`confirmTranslateRecordIncome`（`pages/orderManagement/orderDetail.vue:878`）

对应代码摘录：

```js
// pages/orderManagement/orderDetail.vue:872
let apiPath
if (dateType === 'translateFinishDate') {
  apiPath = path.confirmRecordTranslated
} else if (dateType === 'incomeFinishDate') {
  apiPath = path.confirmTranslateRecordIncome
}
```

保存成功后只刷新生产信息：`pages/orderManagement/orderDetail.vue:885`。

## 11. 常见坑 & 可改进点（面试加分）

1) 结算节点联动目前写在订单详情页：可以抽成通用函数（“先取消再确认”的链路模板），并写单测。
2) 新增生产记录后“先刷新拿 id 再更新日期”的流程复杂：如果后端支持一次性创建带日期字段，可大幅简化。
3) 页面存在 `CustomerSettlementCard` 但目前注释掉：建议明确“由 CustomerInfoCard 统一维护结算节点”，避免重复入口（`pages/orderManagement/orderDetail.vue:60`）。
4) 大量刷新逻辑已做“局部刷新”，可进一步做并发刷新（`refreshCustomerInfo/refreshProductionInfo/refreshOperationRecord` 组合）。
