# 资源开发列表-实现详解（big-customer，面向面试）

> 目标：把“资源开发池列表（译员/供应商）”的筛选、列表展示聚合、状态机行内编辑、入库闭环、跳转与性能细节讲清楚，并能指到代码。

## 1. 一句话概括（面试开场）

资源开发列表是资源模块的“开发池工作台”，核心是：

- **筛选 + 搜索**：把复杂筛选收敛在独立组件 `ResourceFilter`
- **信息密度**：在一行里聚合“价格/接单时间/项目/沟通记录”等多维信息
- **状态机**：行内编辑资源状态，只允许流转到下一状态
- **入库闭环**：入库前强校验必填项，校验通过才允许把状态置为 `已入库(120)`

入口页面：`pages/resourceManagement/interpreterAndSuppliers.vue:1`。

## 4. 信息密度：decorateListForDisplay 如何把多维数据拼成可读文本

开发池列表一行里要展示的信息非常多（服务价格/接单时间/项目/沟通），后端返回是 list + 多个子列表（servicePriceList、workingTimeList、projectList、communicationList）。

前端用 `decorateListForDisplay` 做“展示层聚合”，把结构化数组拼成多行文本（bullet 风格），并做一些字段兼容（`associatedProjectName` vs `relatedProjects`）：

- 函数：`pages/resourceManagement/interpreterAndSuppliers.vue:564`

典型示例：

- 服务价格：把 domain/语言对/服务/价格/速度/备注/状态拼成 `• ...`（`pages/resourceManagement/interpreterAndSuppliers.vue:582`）
- 接单时间：把 timezone 转 UTC + 职业状态 + 接单时间 + 不接时间 + 备注拼成 `• ...`（`pages/resourceManagement/interpreterAndSuppliers.vue:626`）
- 沟通记录：列表只展示最近 3 条，tooltip 里最多 5 条（`pages/resourceManagement/interpreterAndSuppliers.vue:705`）

对应代码摘录（展示聚合核心思路）：

```js
// pages/resourceManagement/interpreterAndSuppliers.vue:564
const decorateListForDisplay = (list) => {
  return (list || []).map((item) => {
    let servicePrice = ''
    if (Array.isArray(item.servicePriceList) && item.servicePriceList.length > 0) {
      servicePrice = item.servicePriceList
        .map(sp => {
          const parts = []
          if (sp.domain) parts.push(sp.domain)
          if (sp.sourceLanguage || sp.targetLanguage) {
            const sourceLang = getLabelByValue(sp.sourceLanguage) || sp.sourceLanguage
            const targetLang = getLabelByValue(sp.targetLanguage) || sp.targetLanguage
            parts.push([sourceLang, targetLang].filter(Boolean).join('→'))
          }
          if (sp.service) parts.push(sp.service)
          if (sp.price !== undefined && sp.price !== null) {
            parts.push(`${sp.price}${sp.currency || ''}${sp.unit ? `/${sp.unit}` : ''}`)
          }
          if (sp.status !== undefined && sp.status !== null && sp.status !== '') {
            const statusMap = { '1': '有效', '-1': '无效' }
            parts.push(statusMap[String(sp.status)] || sp.status)
          }
          return '• ' + parts.join('-')
        })
        .join('\n')
    }

    let orderTime = ''
    if (Array.isArray(item.workingTimeList) && item.workingTimeList.length > 0) {
      orderTime = item.workingTimeList
        .filter(wt => wt.workingTimeSlot || wt.professionalStatus || wt.timezone || wt.unavailableStart || wt.workingTimeNotes)
        .map(wt => '• ' + [convertToUTC(wt.timezone), wt.professionalStatus, wt.workingTimeSlot].filter(Boolean).join('-'))
        .join('\n')
    }

    let communication = ''
    let communicationFull = ''
    if (Array.isArray(item.communicationList) && item.communicationList.length > 0) {
      const communications = item.communicationList.map(comm => {
        return '• ' + [transferToString(comm.communicationTime), comm.communicator, comm.record].filter(Boolean).join('-')
      })
      communication = communications.slice(-3).reverse().join('\n')
      communicationFull = communications.slice(-5).reverse().join('\n')
    }

    return { ...item, servicePrice, orderTime, communication, communicationFull }
  })
}
```

面试讲法：

- 这类列表如果直接展示结构化数组会非常难读，所以需要“展示聚合层”；并且要控制展示条数（3 条展示、5 条 tooltip）避免表格行高爆炸。

## 5. 状态机：行内编辑为什么要“只给下一状态”

页面复用了资源状态机：

- 引入：`pages/resourceManagement/interpreterAndSuppliers.vue:504`（`isStatusEditable/getNextStates/statusReverseMap` 等）
- 状态机配置：`config/resourceStatus.js:54`

### A) 生成下拉选项（当前状态 + nextStates）

来源：`pages/resourceManagement/interpreterAndSuppliers.vue:1791`

```js
getAvailableNextStates(currentStatusText) {
  const nextStateTexts = getNextStates(currentStatusText)
  const options = []
  if (currentStatusText && statusReverseMap[currentStatusText] !== undefined) {
    options.push({ label: currentStatusText, value: statusReverseMap[currentStatusText] })
  }
  nextStateTexts.forEach(text => options.push({ label: text, value: statusReverseMap[text] }))
  return options
}
```

面试讲法：

- UI 上只允许选择“当前状态 + 下一步可流转状态”，避免把状态随意跳到任意节点（比如从沟通中直接到已入库）。
- 真正的业务约束仍需后端兜底，但前端可以显著降低误操作概率。

### B) 保存状态变更：入库(120)需要强校验 + 二次确认

来源：`pages/resourceManagement/interpreterAndSuppliers.vue:1835`

- 如果目标状态是 `120`，先走 `validateOnSiteRequired` 校验缺失字段，再弹确认（`pages/resourceManagement/interpreterAndSuppliers.vue:1843`～`pages/resourceManagement/interpreterAndSuppliers.vue:1878`）。
- 非入库状态直接 `performStatusUpdate` 调后端（`pages/resourceManagement/interpreterAndSuppliers.vue:1885`）。

对应代码摘录：

```js
// pages/resourceManagement/interpreterAndSuppliers.vue:1878
if (Number(this.editingStatusValue) === 120) {
  // ... validateOnSiteRequired + 二次确认
  this.$confirm({
    title: '确认入库提示',

}

// 非入库状态，直接执行更新

```

    resourceId: row.id,

## 6. 入库闭环：为什么在列表页也要做 validateOnSiteRequired

入库在业务上是关键节点：入库后资源会进入在场池，被大量用于生产派单与价格结算，因此必须保证信息完整。

列表页提供“直接入库”入口（action 栏）并复用同一套校验逻辑：

- 入库入口：`handleStockIn`（`pages/resourceManagement/interpreterAndSuppliers.vue:1193`）
- 执行入库：`doStockIn`（`pages/resourceManagement/interpreterAndSuppliers.vue:1224`）
- 校验清单：`validateOnSiteRequired`（`pages/resourceManagement/interpreterAndSuppliers.vue:1272`，Promise.allSettled 并行拉基础/测试/签约/领域/语言/价格/级别）

执行入库本质是调用“更新资源开发信息”接口把 `status=120`：

```js
// pages/resourceManagement/interpreterAndSuppliers.vue:1230
const payload = { resourceId: row.id, status: 120, resourceManager: ... }
await this.$http.post(path.updateResourceContact, payload)
```

面试讲法：

- 列表页做校验的价值：减少“点击入库 → 跳详情 → 再点入库”的来回，提高操作效率；
- 详情页也做同样校验（双保险），避免从详情直接入库绕过校验（详见：`docs/面试问答/资源字段权限-状态机-详解.md:1`）。

## 8. 常见坑 & 可改进点（面试加分）

1) `ResourceFilter` 的 `resourceStatusOptions` 与 `config/resourceStatus.js` 存在重复来源（`components/ResourceFilter/ResourceFilter.vue:204`）：建议统一来源，避免状态新增时漏改。
2) `decorateListForDisplay` 负责拼接非常多展示字符串：建议抽成纯函数模块并补单测，避免未来改动引入格式回归。
3) 行内状态编辑目前依赖 `row.resourceStatus`（中文）与 `row.status`（数字）两套字段同时存在：建议统一“状态源字段”，减少字段不同步的风险。
4) 入库校验在列表与详情两处存在重复：可抽成 `utils/resource/validateOnSiteRequired` 复用，并让校验规则与 `fieldPermissions.required` 合并为单一来源。
