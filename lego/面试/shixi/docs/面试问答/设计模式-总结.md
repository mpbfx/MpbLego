# 项目中的设计模式总结（big-customer，面向面试）

> 目标：把项目里“可复用、可扩展、可维护”的设计模式/架构手法总结出来，并配对应代码摘录（含文件:行号），方便面试时讲结构与取舍。

## 1. 一句话概括（面试开场）

这个项目在 Nuxt SSR 里大量使用“配置驱动 + 插件注入 + 模块化组合（工厂/组合）+ 适配器（转换层）+ 指令策略（权限）”来降低页面复杂度，并把可复用业务能力抽到 `utils/` 与 `plugins/`。

## 2. 模式索引（先给面试官“结构图”）

- **依赖注入（DI）/插件模式**：`plugins/http.js:5`、`plugins/axios.js:3`、`plugins/validateForm.js:1`
- **策略模式（Strategy）**：错误码处理、请求提交格式、权限判定：`plugins/http.js:28`、`plugins/checkPermission.js:9`
- **工厂函数（Factory）+ 组合（Composition）**：卡片数据/方法生成：`utils/resource/useLanguageLevel.js:12`、`utils/resource/useResume.js:103`
- **适配器/转换层（Adapter/Mapper）**：后端数据 -> 前端模型：`utils/resourceDetailTransform.js:13`
- **配置驱动（Configuration-driven）**：权限表、字段权限矩阵、状态机：`config/permission.js:1`、`config/resourceFieldPermission.js:61`、`config/resourceStatus.js:5`
- **门面模式（Facade）**：`$http` 暴露 `get/post` 统一入口：`plugins/http.js:59`
- **模板方法/生命周期编排**：页面 created/mounted 编排模块加载：`pages/translator/index.vue:364`

### 面试讲法

## 4. 策略模式（Strategy）：用参数/配置选择不同策略

```js
post: (url, data, type) => {
  if (type === 'query') { /* x-www-form-urlencoded */ }

```

来源：`plugins/http.js:28`

```js
instance.onResponse(response => {
  if (response.data.errorCode === 1003) { /* redirect/login */ }
  if (response.data.errorCode === 2005) { /* not found */ }
```

### 4.3 权限策略（roleType + label）

### 面试讲法

- 策略模式的核心是“把 if/else 的选择点集中在一个地方”，调用方只传参数（type/label），减少散落判断。

来源：`utils/resourceDetailTransform.js:39`

```js
export function transformTestRecord(item) {
  const testTime = item.testDate ? item.testDate.split(' ')[0] : formatTimestamp(item.createTime).split(' ')[0]
  return { id: item.id, testTime, _raw: item }
}
```

### 面试讲法

- 这是典型 Adapter：把后端“不稳定/不统一”的字段格式统一为页面可消费的结构；
- 纯函数更易测试、可复用，避免转换逻辑散落到多个 Vue 组件里。

## 8. 门面模式（Facade）：对外暴露简化接口，屏蔽内部复杂度

### 关键代码摘录

来源：`plugins/http.js:59`

```js
const http = {
  get: (url, params) => instance({ method: 'get', url, params }),
  post: (url, data, type) => { /* type 策略 */ }

```

### 面试讲法

- 页面不直接接触 axios 实例细节（headers/baseURL/interceptors），只通过 `$http.get/post` 完成请求。

## 9. 指令模式（Directive as Policy）：把“DOM 级策略”封装成指令

### 关键代码摘录

来源：`plugins/checkPermission.js:9`

```js
const checkPermission = Vue.directive('checkPermission', (el, binding, vnode) => {
  if (!checkIfVisible(binding.value.roleType, binding.value.label)) {
    const comment = document.createComment(' ')
    el.parentNode.replaceChild(comment, el)
  }
})
```

### 面试讲法

- 用指令把“权限策略 + DOM 替换手段”集中封装，比到处写 `v-if` 更一致。

## 10. 面试收尾（如何把模式讲成“经验”）

- 把“页面复杂度”通过工厂+组合下沉到 `utils/resource/*`，让页面只负责编排；
- 把“规则变化”通过配置驱动（permission/fieldPermission/status）集中管理；
- 把“横切能力”通过 Nuxt 插件注入（http/validate/permission directive），减少重复代码。
