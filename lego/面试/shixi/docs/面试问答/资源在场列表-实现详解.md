# 资源在场列表-实现详解（big-customer，面向面试）

> 目标：把“在场资源池（已入库资源）”的筛选模型、展示聚合、跳转链路、与资源详情/订单联动讲清楚，并能指到代码。

## 1. 一句话概括（面试开场）

资源在场列表是“可立即投入生产的资源池”，核心是：

- **更偏检索与对比**：按译员级别、订单量级、最近接单、价格区间等维度快速筛选
- **信息密度**：一行里展示测试/语言/价格/接单时间/订单数据等
- **联动入口**：跳资源详情、跳简历预览、跳资源历史订单列表

入口页面：`pages/resourceManagement/onSite.vue:1`。

## 3. 接口差异：stored 资源池（在场） vs develop 资源池（开发）

在场池使用 stored 系列接口：

- 默认列表：`getStoredResourcePage`（`config/path.js:28`、`pages/resourceManagement/onSite.vue:700`）
- 条件筛选：`searchStoredResourceListByCondition`（`config/path.js:29`、`pages/resourceManagement/onSite.vue:662`）

对比开发池接口（便于面试说明分池策略）：

- 开发池默认：`getDevelopResourcePage`（`config/path.js:25`）
- 开发池筛选：`searchDevelopResourceListByCondition`（`config/path.js:26`）

对应代码摘录（接口路径枚举）：

```js
// config/path.js:25
// 生产资源管理相关
getSalesTranslatorPage: '/sales/resource/getDevelopResourcePage',
searchResourceListByCondition: '/sales/resource/searchDevelopResourceListByCondition',
```

面试讲法：

- 两个池是“不同生命周期阶段”的资源集合：开发池关注“开发进度/签约”，在场池关注“可用性/接单表现/价格能力”。

### B) 跳简历预览（优先预览最新简历，否则回退到详情简历卡）

来源：`pages/resourceManagement/onSite.vue:770`

- 先查简历文件：`getResourceResumeByResourceIdAndType`（`pages/resourceManagement/onSite.vue:785`）
- 拼下载 url：`pages/resourceManagement/onSite.vue:801`
- 跳预览页：`pages/resourceManagement/onSite.vue:804`
- 无简历则回退到详情页 `#resume`：`pages/resourceManagement/onSite.vue:810`

对应代码摘录：

```js
// pages/resourceManagement/onSite.vue:770
const resumeRes = await this.$http.get(path.getResourceResumeByResourceIdAndType, {
  resourceId: id,
  fileType: 1
})

if (resumeRes.errorCode === 200 && Array.isArray(resumeRes.data) && resumeRes.data.length > 0) {
  const sortedResumes = resumeRes.data.sort((a, b) => {
    const timeA = a.createTime ? new Date(a.createTime).getTime() : 0
    const timeB = b.createTime ? new Date(b.createTime).getTime() : 0
    if (timeA !== timeB) return timeB - timeA
    return (b.id || 0) - (a.id || 0)
  })

  const resumeFile = sortedResumes[0]
  const encodedFileName = encodeURIComponent(resumeFile.fileName || 'resume.pdf')
  const fileUrl = `${path.baseURL}${path.downloadFile}?keyName=${resumeFile.keyName}&fileName=${encodedFileName}`

  this.$router.push({
    path: `/resourceManagement/resumePreview/${id}`,
    query: { url: fileUrl, from: 'onsite' }
  })
} else {
  this.$router.push({ path: `/resourceManagement/resourceDetail/${id}`, hash: '#resume', query: { from: 'onsite' } })
  this.$message.warning('暂无简历文件')
}
```

这条链路的“下载/预览细节”见专题：`docs/面试问答/上传下载-文件预览-详解.md:1`。

## 8. 常见坑 & 可改进点（面试加分）

1) 在场列表与开发列表都有 `decorateListForDisplay`（各自一份）：可以抽到 `utils/resource/listDecorators` 并做单测，避免两边格式不一致。
2) 筛选项“枚举值”现在分散在 OnSiteFilter（如 orderTimeRangeOptions）：建议统一在 `config/`，便于前后端一致。
3) 列表内的 tooltip + clamp 依赖样式：如果列变多或行高变大，需要统一设计“信息密度策略”（只展示最近 N 条、tooltip 展示 M 条）。
