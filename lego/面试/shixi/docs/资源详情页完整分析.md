## 概览

资源详情页 (`pages/resourceManagement/resourceDetail/_id.vue`) 是一个复杂的企业级表单页面，用于管理翻译资源（译员/供应商）的全生命周期信息。

### 核心特性

- **SSR 首屏优化**: 使用 Nuxt.js 的 `asyncData` 钩子实现服务端渲染
- **并行数据加载**: 7个首屏关键接口并行请求，减少等待时间
- **懒加载策略**: 非首屏数据使用 `requestIdleCallback` 延迟加载
- **模块化设计**: 13个功能卡片，每个卡片独立封装
- **可复用逻辑**: 业务逻辑抽离到 `utils/resource/` 目录
- **权限控制**: 基于资源状态的字段级权限管理
- **状态机管理**: 资源状态流转遵循严格的状态机规则

### 页面结构

```
资源详情页
├── 面包屑导航 (Breadcrumb)
├── Tab 导航 (TabNav)
└── 卡片容器 (Cards Container)
    ├── 1. 基础信息 (BasicInfoCard)
    ├── 2. 资源开发 (DevelopmentInfoCard)
    ├── 3. 资源测试 (TestCard)
    ├── 4. 签约结算 (ContractCard)
    ├── 5. 接单时间 (OrderTimeCard)
    ├── 6. 领域工具 (DomainToolCard)
    ├── 7. 语言水平 (LanguageLevelCard)
    ├── 8. 服务价格 (ServicePriceCard)
    ├── 9. 简历项目 (ResumeCard)
    ├── 10. 订单数据 (OrderDataCard)
    ├── 11. 译员评价 (EvaluationCard)
    ├── 12. 沟通管理 (CommunicationCard)
    └── 13. 操作记录 (OperationRecordCard)
```


## 核心架构设计

### 1. 三层架构模式

```
┌─────────────────────────────────────────────────────────┐
│                    视图层 (View Layer)                    │
│  _id.vue + 13个子组件 (BasicInfoCard, DevelopmentCard...)│
└────────────────────┬────────────────────────────────────┘
                     │ Props / Events
┌────────────────────┴────────────────────────────────────┐
│                  逻辑层 (Logic Layer)                     │
│  utils/resource/*.js (可复用的业务逻辑工厂函数)            │
│  - useBasicInfo.js                                       │
│  - useOrderTime.js                                       │
│  - useDomainTool.js                                      │
│  - useLanguageLevel.js                                   │
│  - useServicePrice.js                                    │
│  - useResume.js / useEducation.js / useWorkExperience.js │
└────────────────────┬────────────────────────────────────┘
                     │ HTTP Requests
┌────────────────────┴────────────────────────────────────┐
│                  数据层 (Data Layer)                      │
│  - API 接口 (config/path.js)                             │
│  - 数据转换 (utils/resourceDetailTransform.js)           │
│  - 配置文件 (config/resourceDetailConfig.js)             │
└─────────────────────────────────────────────────────────┘
```

### 2. 组件通信模式

**父子组件通信**:
- 父 → 子: Props 传递数据和方法
- 子 → 父: Events ($emit) 触发保存/取消/清空操作

**示例**:
```vue
<!-- 父组件 _id.vue -->
<basic-info-card
  :basic-info="basicInfo"
  :is-field-editable="isFieldEditable"
  @save="saveBasicInfo"
  @cancel="cancelBasicInfo"
/>

<!-- 子组件 BasicInfoCard.vue -->
<script>
export default {
  props: ['basicInfo', 'isFieldEditable'],
  methods: {
    handleSave() {
      this.$emit('save', this.formData)
    }
  }
}
</script>
```

### 3. 工厂函数模式 (Factory Pattern)

为了避免 `_id.vue` 成为一个 5000+ 行的"上帝对象"，业务逻辑被抽离到工厂函数中：

```javascript
// utils/resource/useBasicInfo.js
export function createBasicInfoMethods(context, options) {
  return {
    async saveBasicInfo() {
      // 表单校验
      // API 调用
      // 状态更新
    },
    cancelBasicInfo() { /* ... */ },
    clearBasicInfo() { /* ... */ }
  }
}

// _id.vue 中使用
created() {
  this.basicInfoMethods = createBasicInfoMethods(this, {
    onSaveSuccess: () => { /* 回调 */ },
    addOperationRecord: (action) => { /* 记录操作 */ }
  })
}
```

**优势**:
- 逻辑复用: 同样的逻辑可在译员平台复用
- 测试友好: 工厂函数可独立测试
- 代码组织: 按功能模块拆分，易于维护

## 状态管理与权限控制

### 1. 资源状态机

资源状态遵循严格的状态机规则，定义在 `config/resourceStatus.js`：

```
新开发(0) ──→ 沟通中(20) ──→ 备选库(40)
   │              │              │
   ↓              ↓              ↓
不合作(-10) ←──────┴──────────────┘
   │
   ↓
测试中(50) ──→ 测试不通过(-20)
   │              │
   ↓              ↓
测试通过(80) ←─────┘
   │
   ↓
签约中(90) ──→ 签约终止(110)
   │
   ↓
签约完成(100)
   │
   ↓
已入库(120) ──→ 已解约(-30)
```

**状态机配置**:
```javascript
export const statusMachine = {
  '新开发': {
    editable: true,
    nextStates: ['沟通中', '不合作', '备选库']
  },
  '测试通过': {
    editable: true,
    nextStates: ['签约中', '测试不通过']
  },
  // ...
}
```

**状态判断函数**:
```javascript
// 判断状态是否可编辑
export function isStatusEditable(status) {
  const config = statusMachine[status]
  return config ? config.editable : false
}

// 获取可选的下一状态
export function getNextStates(currentStatus) {
  const config = statusMachine[currentStatus]
  return config ? config.nextStates : []
}
```

### 2. 字段级权限控制

权限配置在 `config/resourceFieldPermission.js`，根据资源阶段控制字段的可编辑性和可删除性：

**资源阶段划分**:
- **开发阶段**: 新开发 ~ 签约完成 (所有字段可修改、可删除)
- **在场阶段**: 已入库、已解约 (部分字段只读、不可删除)

**权限配置示例**:
```javascript
export const fieldPermissions = {
  basicInfo: {
    name: {
      development: { editable: false, deletable: false, required: true },
      onsite: { editable: false, deletable: false, required: true }
    },
    mobile: {
      development: { editable: true, deletable: true, required: false },
      onsite: { editable: true, deletable: true, required: false }
    }
  },
  development: {
    status: {
      development: { editable: true, deletable: true, required: true },
      onsite: { editable: true, deletable: false, required: true }
    },
    manager: {
      development: { editable: false, deletable: false, required: true },
      onsite: { editable: false, deletable: false, required: true }
    }
  }
}
```

**使用方式**:
```javascript
// _id.vue
import { getFieldPermission } from '~/config/resourceFieldPermission'

methods: {
  isFieldEditable(category, fieldName) {
    const status = this.developmentInfo.status
    const permission = getFieldPermission(category, fieldName, status)
    return permission.editable
  },
  isFieldDeletable(category, fieldName) {
    const status = this.developmentInfo.status
    const permission = getFieldPermission(category, fieldName, status)
    return permission.deletable
  }
}
```

## 性能优化策略

### 1. SSR 首屏优化

**asyncData 钩子**:
```javascript
async asyncData({ params, app }) {
  const id = params.id
  
  // 新建模式：直接返回空数据，无需请求
  if (id === 'new') {
    return { isNewResource: true, basicInfo: {} }
  }
  
  // 编辑模式：并行加载首屏数据
  const [baseRes, testRes, contractRes, ...] = await Promise.allSettled([
    app.$http.get(path.getResourceBase, { resourceId: id }),
    app.$http.get(path.getResourceTestByResourceId, { resourceId: id }),
    // ... 7个关键接口
  ])
  
  return { basicInfo, testRecords, contractInfo, ... }
}
```

**优势**:
- 服务端渲染，首屏内容直接返回 HTML
- 并行请求，耗时 = max(单个接口耗时)
- SEO 友好

### 2. 懒加载策略

**requestIdleCallback 延迟加载**:
```javascript
mounted() {
  // 使用浏览器空闲时间加载非首屏数据
  if (window.requestIdleCallback) {
    window.requestIdleCallback(() => {
      this.loadLazyData()
    }, { timeout: 2000 })
  } else {
    // 降级方案：延迟 1 秒
    setTimeout(() => {
      this.loadLazyData()
    }, 1000)
  }
}

async loadLazyData() {
  // 并行加载次要数据
  const [resumeRes, eduRes, workRes, ...] = await Promise.allSettled([
    this.$http.get(path.getResourceResume, { resourceId: this.resourceId }),
    this.$http.get(path.getResourceEducation, { resourceId: this.resourceId }),
    // ... 12个次要接口
  ])
}
```

**加载优先级**:
1. **首屏必需** (asyncData): 基础信息、资源开发、测试记录、签约信息、接单时间、领域工具、语言水平、服务价格
2. **次要数据** (懒加载): 简历文件、教育经历、工作经历、项目经验、订单数据、评价记录、沟通记录、操作日志

**Object.freeze 冻结静态数据**:

### 3. HTTP 请求封装

使用 Nuxt.js 的 `$http` 插件（基于 axios）：

```javascript
// plugins/http.js
export default function ({ $axios, store, redirect }, inject) {
  const http = {
    async get(url, params = {}) {
      try {
        const res = await $axios.get(url, { params })
        return res.data
      } catch (error) {
        console.error('GET 请求失败:', error)
        throw error
      }
    },
    async post(url, data = {}) {
      try {
        const res = await $axios.post(url, data)
        return res.data
      } catch (error) {
        console.error('POST 请求失败:', error)
        throw error
      }
    }
  }
  
  inject('http', http)
}
```

**使用示例**:
```javascript
// 获取数据
const res = await this.$http.get(path.getResourceBase, { resourceId: id })
if (res.errorCode === 200) {
  this.basicInfo = res.data
}
```

### 1. 新建资源流程

### 2. 资源测试唯一性校验

```javascript
async checkAdmissionTestUniqueOnServer(excludeId) {
  try {
    const res = await this.$http.get(path.hasBaseResourceTest, {
      resourceId: this.resourceId

    const hasOnServer = res.errorCode === 200 && res.data.hasBaseTest === true

  }
}
```

```javascript
    // 数据未加载，重新加载
    this.loadBasicInfo(this.resourceId)
  }
}
```
