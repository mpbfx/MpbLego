## 资源管理页面性能优化重构总结

### 问题背景

资源管理页面（`interpreterAndSuppliers.vue` 和 `onSite.vue`）存在两个性能问题：
1. 筛选区输入时明显卡顿
2. 点击"自定义表头"按钮展开下拉框时卡顿

**根本原因**：页面组件体量过大（3000+ 行代码，包含 50 行表格），任何响应式数据变化都会触发整个组件重新渲染。

### 解决方案

利用 Vue 组件边界隔离重渲染范围，将频繁触发状态变化的 UI 区域提取为独立子组件。

### 新增组件

| 组件 | 路径 | 用途 |
|------|------|------|
| ResourceFilter | `components/ResourceFilter/ResourceFilter.vue` | 资源开发管理页筛选区 |
| OnSiteFilter | `components/ResourceFilter/OnSiteFilter.vue` | 资源在场管理页筛选区 |
| CustomColumnDropdown | `components/Table/CustomColumnDropdown.vue` | 自定义表头下拉框（通用） |

### 修改文件

| 文件 | 修改内容 |
|------|----------|
| `pages/resourceManagement/interpreterAndSuppliers.vue` | 引入 ResourceFilter、CustomColumnDropdown，移除内联筛选代码和相关样式 |
| `pages/resourceManagement/onSite.vue` | 引入 OnSiteFilter、CustomColumnDropdown，移除内联筛选代码和相关样式 |
| `config/path.js` | 添加在场资源 API 路径 (`getStoredResourcePage`, `searchStoredResourceListByCondition`) |

### 架构变化

```
重构前:
┌─────────────────────────────────────┐
│ Page Component (3000+ lines)        │
│ ├── 筛选区 (内联)                    │ ← 输入触发整页重渲染
│ ├── 自定义表头下拉框 (内联)           │ ← 展开触发整页重渲染
│ ├── 表格 (50行数据)                  │
│ └── 弹窗等                           │
└─────────────────────────────────────┘

重构后:
┌─────────────────────────────────────┐
│ Page Component                      │
│ ├── <ResourceFilter />              │ ← 独立组件，内部重渲染
│ ├── <CustomColumnDropdown />        │ ← 独立组件，内部重渲染
│ ├── 表格 (50行数据)                  │
│ └── 弹窗等                           │
└─────────────────────────────────────┘
```

### 组件通信设计

**筛选组件**：通过事件传递筛选参数
- `@search` - 搜索框回车/点击搜索
- `@filter` - 点击筛选按钮
- `@reset` - 点击重置按钮

**自定义表头组件**：通过 v-model 双向绑定
- Props: `columns`（可选列配置）、`value`（已选列）、`storageKey`（localStorage 键名）
- Events: `@input`、`@change`

### API 参数映射（onSite.vue）

| 组件字段 | API 参数 |
|----------|----------|
| translatorLevel | level |
| orderTimeRange | latestOrderTime |
| motherTongue | language |
| relatedProject | associatedProjectName |
| resourceType | translatorType |

### 移除的冗余代码

**从页面组件移除**：
- `customColumnVisible` 状态
- `handleColumnChange` 方法
- 筛选相关的 20+ 个 data 字段
- `handleFilter`、`resetSearch`、`toggleFilterExpand` 等方法
- `.filter-panel`、`.search-header`、`.custom-column-dropdown` 等样式

### 性能提升效果

| 操作 | 重构前 | 重构后 |
|------|--------|--------|
| 筛选区输入 | 触发整页重渲染（卡顿） | 仅筛选组件重渲染（流畅） |
| 展开自定义表头 | 触发整页重渲染（卡顿） | 仅下拉组件重渲染（流畅） |
| 点击筛选/搜索 | 正常 | 正常 |

### 保持的功能一致性

- 筛选字段、选项值完全一致
- API 请求参数映射正确
- 展开/收起状态持久化到 localStorage
- 自定义列选择持久化到 localStorage
- 样式与原实现一致
