# 微信小程序

#### 说说微信小程序的架构?

微信小程序的架构主要由 前端框架 和 后端服务 组成。前端框架基于Web技术栈，包括javaScript、HTML和CSS，用于构建小程序的界面和逻辑。

前端框架提供了WXML和WXSS用于描述页面结构和样式，以及JavaScript框架和小程序框架来处理用户交互、网络请求和数据绑定等。在架构中，微信小程序还有渲染层和逻辑层两个关键执行环境。

1. 渲染层负责页面的渲染和样式
2. 逻辑层负责处理小程序的逻辑和数据处理

这两个层级通过微信客户端提供的WebView通信机制进行数据传递和事件触发。

除了前端框架，微信小程序还涉及后端服务。微信提供了后端服务，包括用户身份验证、数据存储、消息推送等功能，同时还提供了云开发能力，简化了后端服务的搭建和管理过程。此外，微信小程序还有组件库用于构建各种界面元素和交互组件，调试工具用于代码调试和页面预览，以及小程序管理后台用于管理和发布小程序，

总而言之，微信小程序的架构是基于前端框架和后端服务的，同时涉及渲染层、逻辑层、组件库、调试工具和小程序管理后台等组件和模块，共同构成了一个完整的微信小程序系统

#### 为什么小程序里拿不到dom相关的api?

微信小程序采用了类似于Web的WXML和WXSS语言来描述页面结构和样式，但是却没有提供直接操作DOM的API

这是因为小程序本身是在一个javaScript环境中运行的，其选用的是]avaScriptCore引擎，而不是浏览器中常见的V8引擎。JavaScriptCore与V8引擎的实现方式存在较大差异，其中一个显著的特点是JavaScriptCore的执行速度较慢。

对于小程序开发者来说，直接操作DOM会比较耗时，会导致性能下降和体验差，另外，小程序的设计初衷也是为了提供一种更轻量级、更快速启动的应用方式，它的定位是“去中心化、低门槛高灵活性”的。如果允许开发者直接操作DOM，那么就可能会打破这种设计理念，增加小程序的复杂性和开发难度。

因此，微信小程序暂时不支持直接操作DOM。开发者需要通过其他方式来实现类似的功能，例如使用组件或自定义组件，利用微信小程序提供的API进行页面渲染和交互。

#### 小程序的双线程分别做的什么事情?

双线程指的是客户端运行时有两个线程，分别是渲染线程和逻辑线程，

1. 渲染线程:负责渲染界面，包括解析WXML和WXSS、样式计算、布局排版和绘制视图等操作
2. 逻辑线程:负责处理业务逻辑和数据处理，包括调用小程序API、处理事件、请求网络等操作

通过双线程协同工作，可以实现小程序的高性能和流畅体验

* 当界面需要进行更新时，渲染线程会优先响应，避免造成卡顿;
* 而逻辑线程则负责处理复杂的业务逻辑，不会对界面染产生影响。

这种设计可以有效地提高小程序的运行效率，同时也能够更好地满足用户对于小程序的使用需求。

#### 简述微信小程序原理?

小程序本质就是一个单页面应用，所有的页面渲染和事件处理，都在一个页面内进行，但又可以通过微信客户端调用原生的各种接口;

它的架构，是数据驱动的架构模式，它的UI和数据是分离的，所有的页面更新，都需要通过对数据的更改来实现;

它从技术讲和现有的前端开发差不多，采用JavaScript、WXML、WXSS三种技术进行开发;

功能可分为webview和appService两个部分;

webview用来展现UI，appService有来处理业务逻辑、数据及接口调用:

两个部分在两个进程中运行，通过系统层JSBridge实现通信，实现UI的渲染、事件的处理等

#### 微信小程序的优劣势?

优势

```plain
无需下载，通过搜索和扫一扫就可以打开。
良好的用户体验:打开速度快。
开发成本要比App要低。
安卓上可以添加到桌面，与原生App差不多。
为用户提供良好的安全保障。小程序的发布，微信拥有一套严格的审查流程，不能通过审查的小程序是无法发布到线上的
```

劣势:

```plain
限制较多。页面大小不能超过1M。不能打开超过5个层级的页面，
样式单一。小程序的部分组件已经是成型的了，样式不可以修改。例如:幻灯片、导航。
推广面窄，不能分享朋友圈，只能通过分享给朋友，附近小程序推广。其中附近小程序也受到微信的限制
依托于微信，无法开发后台管理功能。
```

#### 微信小程序bindtap 和 catchtap 区别?

| **特性维度** | <code>**bindtap**</code> | <code>**catchtap**</code> |
| :--- | :--- | :--- |
| **事件冒泡** | **允许**事件向父级组件冒泡  | **阻止**事件向父级组件冒泡  |
| **核心区别** | 点击子组件时，父组件的同名点击事件也会被触发  | 点击子组件时，事件在此处停止，不会影响父组件  |
| **典型场景** | 独立的按钮点击、列表项点击等普通交互  | 弹窗内容区、嵌套列表项中需要隔离点击行为的场景  |
| **写法变体** | `bindtap`或 `bind:tap`（两者等价） | `catchtap`或 `catch:tap`（两者等价） |

#### 小程序 WXSS 与 CSS 的区别?

<font style="color:rgb(0, 0, 0);">理解WXSS和CSS的区别对于小程序开发至关重要。简单来说，WXSS可以看作是CSS的一个“子集”加上一些为小程序量身定做的“扩展”。它们的关系和核心区别可以通过下表快速掌握：</font>

| **特性维度** | **WXSS (微信小程序)** | **CSS (网页)** |
| :--- | :--- | :--- |
| **运行平台** | 微信小程序环境 | 各类Web浏览器 |
| **核心单位** | <code>**rpx**</code> (响应式像素)，可自动适配不同屏幕宽度 | `px`, `em`, `rem`, `%`, `vh`, `vw`等 |
| **样式作用域** | **局部样式**：页面样式默认不影响组件，组件样式不影响页面 | **全局样式**：默认是全局作用域，容易造成样式冲突 |
| **选择器支持** | 较少。主要支持基础选择器，**不支持**复杂的伪类和伪元素（如`:hover`, `::before`) | 非常丰富。支持全部CSS选择器，包括属性选择器、各种伪类、伪元素等 |
| **样式导入** | 使用 `@import`语句 | 使用 `@import`规则 |
| **样式隔离机制** | 提供完善的**样式隔离**配置选项（如`styleIsolation`），有效避免样式污染 | 依赖命名约定（如BEM）或CSS Modules等外部方案解决 |

##### 深入理解关键差异

###### 1. rpx：专为移动端适配而生

<code><font style="color:rgb(0, 0, 0);">rpx</font></code><font style="color:rgb(0, 0, 0);">是WXSS中最实用的特性。它将以</font>**<font style="color:rgb(0, 0, 0);">750物理像素宽</font>**<font style="color:rgb(0, 0, 0);">作为基准，这意味着在宽度为750物理像素（如iPhone 6/7/8的375逻辑像素，DPR=2）的设备上，</font><code><font style="color:rgb(0, 0, 0);">1rpx</font></code><font style="color:rgb(0, 0, 0);">就等于 </font><code><font style="color:rgb(0, 0, 0);">1物理像素</font></code><font style="color:rgb(0, 0, 0);">。在不同宽度的屏幕上，rpx会自动进行等比缩放，极大简化了多端适配的工作量</font>

###### 2. 样式作用域：局部与全局的差异

<font style="color:rgb(0, 0, 0);">这是WXSS和CSS在设计哲学上的一个根本不同。</font>

* **<font style="color:rgb(0, 0, 0);">WXSS</font>**<font style="color:rgb(0, 0, 0);">：默认情况下，每个页面的</font><code><font style="color:rgb(0, 0, 0);">.wxss</font></code><font style="color:rgb(0, 0, 0);">文件中的样式只对当前页面生效；每个自定义组件的样式只对组件内部生效。这种局部作用域的设计，可以有效避免不同页面或组件间的样式相互干扰。你还可以通过配置</font><code><font style="color:rgb(0, 0, 0);">styleIsolation</font></code><font style="color:rgb(0, 0, 0);">属性，更精细地控制页面与组件、组件与组件之间的样式影响关系</font>**<font style="background-color:rgba(0, 0, 0, 0.05);"></font>**<font style="color:rgb(0, 0, 0);">。</font>
* **<font style="color:rgb(0, 0, 0);">CSS</font>**<font style="color:rgb(0, 0, 0);">：传统CSS是全局的。这意味着在任何一个样式文件中定义的规则，都可能影响到整个网站的其他部分，需要开发者小心翼翼地通过命名和管理来避免冲突。</font>

###### 3. 选择器：功能与性能的权衡

<font style="color:rgb(0, 0, 0);">WXSS为了保持简洁性和运行效率，选择不支持一部分CSS中复杂的选择器，尤其是那些可能影响性能或与小程序逻辑层交互不便的伪类和伪元素，比如</font><code><font style="color:rgb(0, 0, 0);">:hover</font></code><font style="color:rgb(0, 0, 0);">（部分平台支持有限）和</font><code><font style="color:rgb(0, 0, 0);">::before</font></code><font style="color:rgb(0, 0, 0);">。这要求开发者在编写样式时采用更直接的方式。</font>

##### 开发实践建议

1. **<font style="color:rgb(0, 0, 0);">单位选择</font>**<font style="color:rgb(0, 0, 0);">：在涉及布局、尺寸（如宽度、边距、字体大小）时，</font>**<font style="color:rgb(0, 0, 0);">优先使用</font>**<code>**<font style="color:rgb(0, 0, 0);">rpx</font>**</code><font style="color:rgb(0, 0, 0);">，以实现响应式适配。对于需要精确到物理像素的细边框等场景，可考虑使用</font><code><font style="color:rgb(0, 0, 0);">px</font></code>**<font style="background-color:rgba(0, 0, 0, 0.05);"></font>**<font style="color:rgb(0, 0, 0);">。</font>

3. \*\*\*\***<font style="color:rgb(0, 0, 0);">交互反馈</font>**<font style="color:rgb(0, 0, 0);">：由于WXSS对</font><code><font style="color:rgb(0, 0, 0);">:hover</font></code><font style="color:rgb(0, 0, 0);">等伪类支持有限，实现类似按钮按下的效果，应使用小程序组件内置的属性，如</font><code><font style="color:rgb(0, 0, 0);">view</font></code><font style="color:rgb(0, 0, 0);">组件的</font><code><font style="color:rgb(0, 0, 0);">hover-class</font></code><font style="color:rgb(0, 0, 0);">，或通过JavaScript动态修改类名。</font>

WXML--模板文件

#### 微信小程序与vue区别

* 生命周期不一样，微信小程序生命周期比较简单
* 数据绑定也不同，微信小程序数据绑定需要使用 {{}} vue 直接 :就可以
* 显示与隐藏元素， vue 中，使用 v-if 和 v-show 控制元素的显示和隐藏，小程序中，使用 wx-if 和 hidden 控制元素的显示和隐藏
* 事件处理不同，小程序中，全用 bindtap(bind+event)，catchtap(catch+event)绑定事件,vue:使用 v-on:event 绑定事件，或者使用@event 绑定事件
* 数据双向绑定也不一样 在 vue 中,只需要再表单元素上加上 v-model,然后再绑定data 中对应的一个值，当表单元素内容发生变化时，data 中对应的值也会相应改变这是 vue 非常 nice 的一点。微信小程序必须获取到表单元素改变的值，然后再把值赋给一个 data中声明的变量。

| **编译转换层** | 源代码到多端产物的转换 | **条件编译**：通过 `#ifdef`/`#endif`在编译时按平台保留或剔除代码块。<br/>**特定转换**：将 Vue 模板、样式、JS 编译成各平台目标代码，如小程序 WXML/WXSS、H5 的 HTML/CSS、App 端的 JS 或原生代码 | 实现平台差异化处理，保证一套代码能生成各平台可识别的专属格式，是实现“一次编写，多端输出”的关键。 |
| **运行时与渲染层** | 在各端环境中执行代码和渲染界面 | **运行时封装**：提供统一的 `uni`API，在运行时根据平台调用对应的原生 API（如微信的 `wx.request`或浏览器的 `fetch`）。<br/>**双引擎渲染**：   1. **Web渲染**：默认模式，使用各平台 WebView，适合大多数应用场景。   2. **原生渲染 (NVue)**：将组件编译为原生组件，由原生渲染引擎绘制，性能更高，适合复杂列表和动画 | 屏蔽底层平台接口差异，保证代码在各端行为一致。提供不同的渲染模式以适应不同场景的性能需求，在开发效率和体验间取得平衡。 |

#### <font style="color:rgba(0, 0, 0, 0.9);background-color:rgb(243, 243, 243);">微信小程序里的登录和h5页面的登录有什么区别</font>

| **对比维度** | **微信小程序登录** | **H5页面登录** |
| :--- | :--- | :--- |
| **技术原理** | 调用小程序API（如`wx.login()`）获取临时凭证`code` | 基于OAuth 2.0协议，通过页面重定向到微信授权页获取`code` |
| **用户体验** | **无感/静默登录**，启动时自动完成，体验流畅 | **需手动授权**，会跳转页面，流程中断感明显 |
| **信息获取** | 可获取用户的**唯一标识OpenID**；经用户授权后，可安全获取**微信绑定手机号** | 可获取用户的**唯一标识OpenID**、昵称和头像等基础信息；**无法直接获取手机号** |
| **登录态管理** | 依赖微信提供的`session_key`及自维护的`token`，在微信封闭环境内管理，相对简单 | 依赖后端生成的`token`，通常在`localStorage`或`Cookie`中维护，需处理跨域等安全问题 |
| **审核与上线** | **需要提交腾讯审核**，每次更新版本都需重新审核，周期不定 | **无需平台审核**，可随时更新上线，非常灵活 |
| **适用场景** | 适合微信生态内**高频使用、功能复杂、追求原生体验**的服务类应用 | 适合**营销活动、快速迭代、跨平台传播**或需要分享到朋友圈的场景 |

##### 如何选择及注意事项

<font style="color:rgb(0, 0, 0);">面对具体项目时，你可以参考以下思路进行选择：</font>

1. \*\*\*\***<font style="color:rgb(0, 0, 0);">根据核心目标抉择</font>**

* **<font style="color:rgb(0, 0, 0);">追求极致用户体验和功能深度</font>**<font style="color:rgb(0, 0, 0);">：如果您的应用深度依赖微信生态，希望为用户提供无缝、流畅的体验，并且可能需要使用手机号等更高级的权限，</font>**<font style="color:rgb(0, 0, 0);">微信小程序是更优选择</font>**<font style="color:rgb(0, 0, 0);">。</font>
* **<font style="color:rgb(0, 0, 0);">注重快速迭代和广泛传播</font>**<font style="color:rgb(0, 0, 0);">：如果您的项目是活动页、宣传页，需要快速上线、频繁调整，或者需要分享到朋友圈以最大化曝光，</font>**<font style="color:rgb(0, 0, 0);">H5页面更具优势</font>\*\*\*\*<font style="background-color:rgba(0, 0, 0, 0.05);"></font>**<font style="color:rgb(0, 0, 0);">。</font>

2. **<font style="color:rgb(0, 0, 0);">注意用户标识的区别</font>**<font style="color:rgb(0, 0, 0);">需要注意的是，同一个用户在同一家公司的</font>**<font style="color:rgb(0, 0, 0);">小程序和H5页面中，其OpenID是不同的</font>**<font style="color:rgb(0, 0, 0);">。如果你需要识别这是同一个人，必须在微信开放平台将小程序和公众号（H5）绑定到同一个账号下，通过获取用户唯一的 </font>**<font style="color:rgb(0, 0, 0);">UnionID</font>**<font style="color:rgb(0, 0, 0);"> 来实现身份统一</font>**<font style="background-color:rgba(0, 0, 0, 0.05);"></font>**<font style="color:rgb(0, 0, 0);">。</font>
3. **<font style="color:rgb(0, 0, 0);">考虑小程序内嵌H5的特殊情况,</font>**<font style="color:rgb(0, 0, 0);">小程序内部可以通过WebView组件嵌入H5页面。在这种情况下，登录流程会变得复杂，需要建立</font>**<font style="color:rgb(0, 0, 0);">小程序与H5之间的通信机制</font>**<font style="color:rgb(0, 0, 0);">（如通过URL参数传递登录态），以确保两者间的登录状态同步</font>**<font style="background-color:rgba(0, 0, 0, 0.05);"></font>**<font style="color:rgb(0, 0, 0);">。</font>

#### 微信小程序如何获取用户手机号

##### 前端开发要点

1. **<font style="color:rgb(0, 0, 0);">使用特定的Button组件</font>**

<font style="color:rgb(0, 0, 0);">获取手机号的能力必须通过一个将 </font><code><font style="color:rgb(0, 0, 0);">open-type</font></code><font style="color:rgb(0, 0, 0);">设置为 </font><code><font style="color:rgb(0, 0, 0);">getPhoneNumber</font></code><font style="color:rgb(0, 0, 0);">的按钮来触发，由用户主动点击。不能通过API自动调用</font>**<font style="background-color:rgba(0, 0, 0, 0.05);">17</font>**<font style="color:rgb(0, 0, 0);">。</font>

```html
<button open-type="getPhoneNumber" bindgetphonenumber="getPhoneNumber">授权手机号登录</button>
```

2. **<font style="color:rgb(0, 0, 0);">处理授权回调事件</font>**

<font style="color:rgb(0, 0, 0);">用户点击按钮同意后，你可以在绑定的事件回调函数中获取到微信返回的加密数据</font>

```javascript
Page({
  getPhoneNumber(e) {
    if (e.detail.errMsg === 'getPhoneNumber:ok') {
      // 用户同意授权
      const { code, encryptedData, iv } = e.detail; // 新版本接口会返回code
      // 将这些数据发送给你的后端服务器
      wx.request({
        url: '你的后端API地址',
        method: 'POST',
        data: {
          code: code, // 注意：这个code用于后端换取手机号，和wx.login()获取的code不同
          // 如果使用旧版接口，则传递 encryptedData 和 iv
          // encryptedData: encryptedData,
          // iv: iv
        },
        success (res) {
          // 后端解密成功后会返回明文手机号
          console.log('用户手机号:', res.data.phoneNumber);
        }
      });
    } else {
      // 用户拒绝授权
      console.log('用户拒绝了授权');
    }
  }
})
```

**<font style="color:rgb(0, 0, 0);">重要提示</font>**<font style="color:rgb(0, 0, 0);">：自微信基础库2.21.0起，推荐使用新版获取手机号方式，即主要传递 </font><code><font style="color:rgb(0, 0, 0);">code</font></code><font style="color:rgb(0, 0, 0);">给后端，由后端直接调用微信接口获取手机号，这比前端传 </font><code><font style="color:rgb(0, 0, 0);">encryptedData</font></code><font style="color:rgb(0, 0, 0);">和 </font><code><font style="color:rgb(0, 0, 0);">iv</font></code><font style="color:rgb(0, 0, 0);">再由后端解密更简单可靠</font>**<font style="background-color:rgba(0, 0, 0, 0.05);"></font>**<font style="color:rgb(0, 0, 0);">。</font>

##### 后端处理逻辑

<font style="color:rgb(0, 0, 0);">后端需要完成解密（旧版）或直接调用微信接口（新版）的关键任务</font>

1. **<font style="color:rgb(0, 0, 0);">获取会话密钥（Session Key）</font>**<font style="color:rgb(0, 0, 0);">无论是新旧方式，后端首先都需要使用小程序前端调用 </font><code><font style="color:rgb(0, 0, 0);">wx.login()</font></code><font style="color:rgb(0, 0, 0);">获得的登录凭证 </font><code><font style="color:rgb(0, 0, 0);">code</font></code><font style="color:rgb(0, 0, 0);">（注意，这是另一个code），来向微信服务器请求获取该用户的 </font><code><font style="color:rgb(0, 0, 0);">session_key</font></code><font style="color:rgb(0, 0, 0);">和 </font><code><font style="color:rgb(0, 0, 0);">openid</font></code>**<font style="background-color:rgba(0, 0, 0, 0.05);"></font>**

```plain
GET https://api.weixin.qq.com/sns/jscode2session?appid=APPID&secret=SECRET&js_code=CODE&grant_type=authorization_code
```

2. \*\*\*\***<font style="color:rgb(0, 0, 0);">解密手机号（主要针对旧版方式）</font>**

* **<font style="color:rgb(0, 0, 0);">旧版路径</font>**<font style="color:rgb(0, 0, 0);">：如果前端传递的是 </font><code><font style="color:rgb(0, 0, 0);">encryptedData</font></code><font style="color:rgb(0, 0, 0);">和 </font><code><font style="color:rgb(0, 0, 0);">iv</font></code><font style="color:rgb(0, 0, 0);">，后端需要使用获取到的 </font><code><font style="color:rgb(0, 0, 0);">session_key</font></code><font style="color:rgb(0, 0, 0);">以及 </font><code><font style="color:rgb(0, 0, 0);">appId</font></code><font style="color:rgb(0, 0, 0);">，通过AES-128-CBC算法对加密数据进行解密，从而获得包含手机号的JSON对象</font>**<font style="background-color:rgba(0, 0, 0, 0.05);"></font>**<font style="color:rgb(0, 0, 0);">。</font>
* **<font style="color:rgb(0, 0, 0);">新版推荐路径</font>**<font style="color:rgb(0, 0, 0);">：如果前端传递的是获取手机号时返回的 </font><code><font style="color:rgb(0, 0, 0);">code</font></code><font style="color:rgb(0, 0, 0);">，后端在获取 </font><code><font style="color:rgb(0, 0, 0);">access_token</font></code><font style="color:rgb(0, 0, 0);">后，可直接调用微信的 </font><code><font style="color:rgb(0, 0, 0);">getPhoneNumber</font></code><font style="color:rgb(0, 0, 0);">接口换取手机号，无需自行解密</font>**<font style="background-color:rgba(0, 0, 0, 0.05);"></font>**<font style="color:rgb(0, 0, 0);">。</font>

```javascript
// 以Node.js为例的解密核心逻辑（旧版）
const crypto = require('crypto');
function decryptData(sessionKey, encryptedData, iv, appId) {
  const sessionKeyBase64 = Buffer.from(sessionKey, 'base64');
  const encryptedDataBase64 = Buffer.from(encryptedData, 'base64');
  const ivBase64 = Buffer.from(iv, 'base64');
  let decoded;
  try {
    const decipher = crypto.createDecipheriv('aes-128-cbc', sessionKeyBase64, ivBase64);
    decipher.setAutoPadding(true);
    decoded = Buffer.concat([decipher.update(encryptedDataBase64), decipher.final()]);
    decoded = JSON.parse(decoded.toString());
  } catch (err) {
    throw new Error('解密失败');
  }
  // 验证appid是否匹配
  if (decoded.watermark.appid !== appId) {
    throw new Error('AppID不匹配');
  }
  return decoded; // decoded.phoneNumber 即为用户手机号
}
```
